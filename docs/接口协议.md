# 接口协议（本地 HTTP 服务）

> 这份文件是**接口契约**：其他工程接入 mmd2vsdx 时，路由、请求形态、响应头、
> 错误码、状态码、上限常量都以本文为准。契约版本 `1`；同一契约版本内向后兼容，
> 破坏性变更升版本号并在这里登记。
>
> 形态一句话：**POST 送 mermaid 原文，响应体就是 `.vsdx` 字节**。服务既不读文件，
> 也不写文件，产物由调用方自己接收、自己保存。
>
> 覆盖范围：本机常驻 HTTP 服务。对外监听、鉴权、MCP 不在本期范围，
> 结论与缺口见 [待讨论功能备忘.md](待讨论功能备忘.md)。
>
> 历史上的命令行与库引入两条入口已移除，对外只保留这份 HTTP 契约；
> 需要旧用法时从 git 历史里翻。

## 1. 形态与边界

其他工程调用我们只有一种方式：在本机起一个常驻服务进程，然后发 HTTP 请求。

- 请求体是 mermaid 原文，`Content-Type: text/plain; charset=utf-8`；
- 响应体是 `.vsdx` 字节，`Content-Type: application/vnd.ms-visio.drawing`；
- 元数据走响应头，不掺进字节流，调用方拿到字节可以直接落盘或嵌进自己的文档；
- **服务不落盘**：没有输出目录参数、没有覆盖开关、没有临时文件。落盘、命名、
  保留策略全归调用方；
- **服务不接受任何路径参数**：不读输入文件，也不写产物文件。

不落盘带来两个直接结果。一是没有越权读写的面，安全只需守住回环监听；
二是省掉了路径归一、覆盖冲突、半写产物这一整类问题，服务退化成一个纯函数。

## 2. 启动与前置条件

前置条件两条：

| 项 | 要求 |
| --- | --- |
| Node | 22.2 以上 |
| Chromium | 渲染 mermaid 要用，装一次即可：`npx playwright install chromium` |

启动：

```bash
node bin/mmd2vsdx-server.mjs                    # 默认端口 12138
node bin/mmd2vsdx-server.mjs --port 12138 --idle-browser 300
npx mmd2vsdx-server                             # 装进工程后
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--port <n>` | 12138 | 监听端口；只绑 `127.0.0.1`，不接受指定其它地址 |
| `--idle-browser <秒>` | 300 | 空闲这么久且在途请求为零就关掉 Chromium；`0` 表示不回收 |
| `--timeout <秒>` | 15 | 单请求渲染超时，超时回 504 |
| `--version` | — | 打印服务版本后退出 |
| `-h` / `--help` | — | 打印参数表后退出 |

同名环境变量 `MMD2VSDX_PORT`、`MMD2VSDX_IDLE_BROWSER`、`MMD2VSDX_TIMEOUT`，
日志级别另有 `MMD2VSDX_LOG`，取值 `silent`、`error`、`info`、`debug`，默认 `info`。
命令行参数优先于环境变量，环境变量优先于默认值。

启动后进程立刻在后台预热浏览器，预热不占请求队列。启动期间的退出码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 正常退出；或者探测到端口上已有**本家且契约版本兼容**的实例，静默让位 |
| 1 | 启动失败，例如端口绑定被系统拒绝 |
| 2 | 用法错误，未知参数或缺值 |
| 3 | 端口被**非本服务**占用，不要盲目重试 |

默认端口 `12138` 是**公开契约的一部分**，改了会让既有调用方连不上；
需要并存多个实例时用 `--port` 显式错开。

## 3. 路由

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/health` | 就绪探测、版本确认、队列观察 |
| `POST` | `/convert` | mermaid 原文进，`.vsdx` 字节出 |

路径不在表内回 404，方法不符回 405 并在 `Allow` 头里列出允许的方法。
将来若有破坏性变更，新增 `/v2/...` 路径，`/health` 的 `contractVersion` 一并升。

## 4. POST /convert

### 4.1 请求

| 项 | 要求 |
| --- | --- |
| 方法 | `POST` |
| `Content-Type` | `text/plain`，`charset` 省略或为 `utf-8` |
| 请求体 | mermaid 原文，UTF-8 编码，不超过 `kMaxInputBytes`（256KB） |
| 编码 | 只接受 `identity`；带 `Content-Encoding` 一律回 415 |
| 其它参数 | 无。不需要查询串，不需要 JSON 包体 |

输入为空或全是空白回 400 `parse_error`。内容类型或字符集不对回 415，
图型不在支持清单内回 400 `unsupported_kind`，语法错误回 400 `parse_error`。

### 4.2 成功响应

```
HTTP/1.1 200 OK
Content-Type: application/vnd.ms-visio.drawing
Content-Length: 10357
Cache-Control: no-store
Content-Disposition: attachment; filename="flow.vsdx"; filename*=UTF-8''flow.vsdx
X-Mmd2Vsdx-Version: 0.1.0-alpha3
X-Mmd2Vsdx-Kind: flowchart
X-Mmd2Vsdx-Bytes: 10357
X-Mmd2Vsdx-Sha256: 3f2a...（64 位小写十六进制）
X-Mmd2Vsdx-Page-Width-In: 3.4210
X-Mmd2Vsdx-Page-Height-In: 1.8542
X-Mmd2Vsdx-Shape-Count: 2
```

| 响应头 | 说明 |
| --- | --- |
| `Content-Type` | 固定 `application/vnd.ms-visio.drawing` |
| `Content-Disposition` | 建议文件名，取图标题推导；非 ASCII 标题用 `filename*` 百分号编码 |
| `X-Mmd2Vsdx-Version` | 服务版本，**所有响应都带**，便于调用方确认没连到旧实例 |
| `X-Mmd2Vsdx-Kind` | 图型：`flowchart`、`block`、`class`、`er`、`sequence` |
| `X-Mmd2Vsdx-Bytes` | 响应体字节数，等于 `Content-Length` |
| `X-Mmd2Vsdx-Sha256` | 字节内容哈希，可用于缓存比对与完整性校验 |
| `X-Mmd2Vsdx-Page-Width-In` / `-Height-In` | 页面尺寸，英寸，四位小数 |
| `X-Mmd2Vsdx-Shape-Count` | 页面内形状总数 |
| `X-Mmd2Vsdx-Warnings` | 不阻断的提示，base64 编码的 UTF-8 JSON 字符串数组，无提示时不出现 |

`Warnings` 用 base64 是因为 HTTP 头按规范只保证 ASCII，中文提示直接写进头里会变成
非法的 `obs-text`。解码三步：取头、base64 解码、`JSON.parse`。当前可能有两条：
class 图用了没有官方母版的构造型，或者 sequence 图没有参与者。

### 4.3 例子

```bash
# 一行拿到图：请求体是 mmd 原文，响应体存成文件
curl -sS -X POST http://127.0.0.1:12138/convert \
     -H 'Content-Type: text/plain; charset=utf-8' \
     --data-binary @图.mmd -o 图.vsdx -D 图.headers

# 只看元数据
curl -sS -o /dev/null -D - -X POST http://127.0.0.1:12138/convert \
     --data-binary 'flowchart LR
  A-->B'
```

```ts
// Node 18 以上自带 fetch，不需要额外依赖
const res = await fetch('http://127.0.0.1:12138/convert', {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain; charset=utf-8' },
  body: 'flowchart LR\n  A-->B',
});
if (!res.ok) {
  const { error } = await res.json();           // 失败才是 JSON
  throw new Error(`${error.code}: ${error.message}`);
}
await writeFile('图.vsdx', Buffer.from(await res.arrayBuffer()));
const warnings = res.headers.get('x-mmd2vsdx-warnings');
```

## 5. GET /health

不需要请求体，不鉴权，也**不会**被渲染队列堵住，任何时候都能答。

```json
{
  "ok": true,
  "serviceVersion": "0.1.0-alpha3",
  "contractVersion": 1,
  "chromium": "ready",
  "queue": 0,
  "maxQueue": 32,
  "inFlight": 0,
  "timeoutMs": 15000,
  "uptimeMs": 84120,
  "pid": 24680
}
```

| 字段 | 说明 |
| --- | --- |
| `serviceVersion` | 服务版本，等于包版本 |
| `contractVersion` | 契约版本，本文档的版本号；调用方不兼容就直接报错，别静默降级 |
| `chromium` | `cold` 未启动、`warming` 预热中、`ready` 可用；`cold` 时首个请求要吃冷启动 |
| `queue` / `maxQueue` | 排队中的请求数与上限，到上限新请求回 429 |
| `inFlight` | 正在渲染的请求数，取值 0 或 1 |
| `timeoutMs` | 当前生效的单请求超时 |
| `uptimeMs` / `pid` | 进程启动时长与进程号，运维和排查用 |

调用方建议在启动自己的流程前先打一次 `/health`：确认服务在、契约版本对，
顺便让 `chromium` 从 `cold` 走起来。

## 6. 错误契约

失败一律回 JSON，结构固定：

```json
{
  "ok": false,
  "error": {
    "code": "parse_error",
    "message": "Parse error on line 2: ...",
    "hint": "先用图型关键字开头，例如 flowchart LR"
  }
}
```

`hint` 可能不出现。成功时响应体是字节，不是 JSON，所以**调用方要按状态码分支**：
`2xx` 读字节，其余读 JSON。

| HTTP | code | 触发条件 | 调用方建议动作 |
| --- | --- | --- | --- |
| 400 | `parse_error` | mermaid 语法错误，或请求体为空 | 修文本；把 `message` 回显给用户 |
| 400 | `unsupported_kind` | 图型不在五类支持清单内 | 换图型；`hint` 里列了支持清单 |
| 400 | `invalid_argument` | 其它入参问题 | 修调用参数 |
| 403 | `forbidden` | `Host` 头不是回环地址，或请求带了 `Origin` | 只用本机客户端直连 |
| 404 | `not_found` | 路径不在路由表 | 查路由表 |
| 405 | `method_not_allowed` | 方法不符，响应带 `Allow` | 改用 `POST` 或 `GET` |
| 413 | `too_large` | 输入超 256KB，或产物超 8MB | 把图拆小 |
| 415 | `unsupported_media_type` | 内容类型不是 `text/plain`、字符集不是 UTF-8，或带了 `Content-Encoding` | 改请求头 |
| 429 | `queue_full` | 队列深度到上限，响应带 `Retry-After: 1` | 退避重试 |
| 500 | `internal` | 其它未归类错误 | 把 `message` 连同输入反馈 |
| 503 | `renderer_unavailable` | 浏览器起不来，多半是没装 Chromium | 执行 `npx playwright install chromium` |
| 504 | `timeout` | 单请求超过超时上限 | 重试一次；仍失败就反馈输入 |

上限常量可以直接引用：`kMaxInputBytes`（256KB）、`kMaxOutputBytes`（8MB）、
`kMaxQueue`（32）、`kDefaultTimeoutMs`（15s）。

## 7. 并发、超时与上限

渲染是**串行队列**：一个进程里同时只有一次浏览器渲染在跑，排队的不并行执行。
这是有意的取舍，一份 Chromium 换掉并发带来的内存与稳定性问题。

- 队列深度到 `kMaxQueue`（32）就回 429，避免排队请求把内存吃光；
- 单请求超过 `--timeout`（默认 15 秒）就中断、重建浏览器、回 504。**不要关掉它**：
  一次挂死的渲染会永久占住队列，之后所有请求一起哑掉；
- 预热之后单张图通常几十毫秒。一篇文档十几张图，**串行逐张发**就够快，
  不建议并发轰炸，服务内部本来就排队；
- 想提高吞吐就起多个实例用不同端口，代价是每个实例一份 Chromium 内存；
- 调用方请复用连接，HTTP/1.1 默认的 keep-alive 就够，别每个请求新建连接。

## 8. 生命周期与运维

服务**常驻不退**，退出只发生在收到 `SIGINT`/`SIGTERM` 时，且会先把在途请求做完。

退出行为分两种情况。POSIX 上两个信号都能排空；**Windows 没有真正的信号**，
`taskkill` 与 `process.kill` 都是直接终止，排空不会发生，只有控制台里按
Ctrl+C 走的 `SIGINT` 能正常排空。所以在 Windows 上升级或停服之前，先用
`GET /health` 确认 `inFlight` 与 `queue` 都归零，再停进程。

- 空闲 `--idle-browser` 秒后关掉 Chromium 释放内存，进程留着；进程内队列空且没有
  在途请求才会开始回收，回收途中来的请求等它收完再预热；
- 启动即预热，避免第一个调用方吃冷启动那一秒多；
- **不提供 `/shutdown`**：本机任何进程和网页都能发请求，留一个关机端点等于留一个
  拒绝服务的口子。换实例、升级由部署方负责：停旧进程，再起新的；
  停之前可以打 `/health` 确认在途情况；
- 日志走 stderr，不写文件。谁把它拉起来的、要不要重定向到文件，是拉起方的事；
- 服务不关心谁拉起它，也不和拉起方共生死：**拉起方退出不影响它**。

升级流程固定成三步：`GET /health` 看版本与在途情况，停旧进程，起新进程。
响应头里的 `X-Mmd2Vsdx-Version` 就是给这一步兜底用的，调用方可以顺手断言。

## 9. 安全

默认只做四件事，都是零配置的：

1. 只绑 `127.0.0.1`，不监听任何外部地址；
2. `Host` 头只认 `127.0.0.1:<端口>`、`localhost:<端口>` 与 `[::1]:<端口>`，
   其余一律 403，挡掉 DNS rebinding 那类请求；
3. 带 `Origin` 的请求一律 403。浏览器发的跨站请求都带 `Origin`，而 curl 与
   Node 的 `fetch` 不带，这条把网页挡在门外，对正常调用零成本；
4. 不返回任何 CORS 头，网页即使把请求发出来了也读不到响应。

没有 token。理由是不落盘、不吃路径参数，最坏情况是别人烧你的 CPU 和内存，
拿不到本机任何数据，装 token 的复杂度换不来对等的收益。

**红线**：一旦将来加回「按路径读输入」或「按路径写产物」，上面的结论立即作废，
那时必须补上 token 与路径白名单。要开远程监听同理，还得加 TLS 与反向代理。

## 10. 确定性与稳定性

- **确定性**：同一段 mermaid 原文，两次转换字节一致，`X-Mmd2Vsdx-Sha256` 可直接比对。
  跨机器、跨 Chromium 版本不作保证，版本差异会改渲染结果；
- **承诺稳定**：路由与方法、请求形态、响应头名、错误码集合、状态码映射、上限常量、
  默认端口、启动参数与退出码；
- **不承诺**：产物的 XML 细节与母版命名、`dist/` 内部目录结构；
- **变更登记**：破坏性变更升 `contractVersion` 并在本文开头记一笔。
  当前契约版本 `1`，服务版本 `0.1.0-alpha3`。默认端口在 alpha3 对外发布前
  由 `17321` 调整为 `12138`，此时还没有外部调用方，不单独升契约版本。

## 11. 部署要点

Chromium 从哪来，三种口径：

| 场景 | 做法 |
| --- | --- |
| 开发机 | `npx playwright install chromium` 装一次，缓存在 `%LOCALAPPDATA%\ms-playwright`，同一 Windows 用户下所有调用方共用 |
| 打包分发、离线可用 | `node scripts/pack-offline.mjs`：浏览器装进包内 `browsers/`、生产依赖 `npm ci --omit=dev` 一并打包，产出 `release/mmd2vsdx-offline-<版本>-<平台>.zip`；启动用包内 `start.cmd`（它把 `PLAYWRIGHT_BROWSERS_PATH` 指向包内 `browsers/`）。加 `--verify` 会解包起服务冒烟一次 |
| 多用户共用一台机器 | 把 `PLAYWRIGHT_BROWSERS_PATH` 指到一个公共可读目录，装一次；Playwright 按浏览器构建号分目录，多版本共存不打架，只是各占一份磁盘 |

包是 `private: true`，未发布 npm。服务形态下调用方与本服务是进程关系，不是依赖关系，
所以按 tarball 或目录部署都行，调用方只需要知道服务的地址与端口。

离线包的目标机器只需要 **Node.js ≥ 22**：依赖与 Chromium 都在包内，全程不需要网络。
包结构 `dist/` + `bin/` + `node_modules/`（仅生产依赖）+ `browsers/` + `start.cmd` +
`离线部署说明.md`。

## 12. 当前不提供

- 对外监听、鉴权、TLS、多副本与容器化；
- MCP 接入：HTTP 这一层已经有了，缺的是 MCP 壳与鉴权，见
  [待讨论功能备忘.md](待讨论功能备忘.md)；
- 批量端点：一篇文档多张图就发多个请求，服务内部本来串行；
- 产物落盘、输出目录、覆盖规则：调用方自己接收字节、自己保存；
- 流式与增量输出、渲染进度回调、请求取消。

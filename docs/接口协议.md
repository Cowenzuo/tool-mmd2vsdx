# 接口协议（本地接入）

> 这份文件是**接口契约**：其他工程接入 mmd2vsdx 时，字段名、结构、错误码、退出码
> 以本文为准。库 API 与命令行参数在同一主版本内保持兼容；alpha 期的破坏性变更会
> 升 `alphaN` 并在这里登记。
>
> 覆盖范围：本地库引入与本地命令行。远程服务（MCP 等）不在本期范围，
> 结论与缺口见 `待讨论功能备忘.md` 的 P-5。

## 1. 两种接入方式

| 方式 | 入口 | 适合 |
| --- | --- | --- |
| 库引入 | `mmd2vsdx/service` 导出的 `ServiceSession` | Node 工程内直接调用，进程内复用同一个浏览器 |
| 命令行 | 可执行文件 `mmd2vsdx` | 任意语言、脚本、CI；按 JSON 回执解析 |

包根导出（`mmd2vsdx`）是四步管线 `Parser → renderContract → PartsAssembler → Squeeze`，
可用但**不承诺稳定**：跨工程接入请用 `mmd2vsdx/service` 或命令行。

## 2. 前置条件

- Node 22.2 以上；
- 首次要装 Chromium：`npx playwright install chromium`（渲染 mermaid 用它；浏览器缓存在
  用户目录，装过一次全机共用）；
- 包未发布到 npm（`private: true`），三种接入方式（细节见根 README 的"方式一"）：
  ```bash
  npm install D:/_dev/tool-mmd2vsdx                              # 目录依赖：建目录联接，秒装、改源码立即生效
  npm install ./mmd2vsdx-0.1.0-alpha3.tgz                        # 源仓库 npm pack 出的 tarball，自带 dist 与 bin
  npm install git+https://github.com/Cowenzuo/tool-mmd2vsdx.git  # git 依赖，安装时跑 prepare 构建
  ```
- 环境变量 `MMD2VSDX_OUTPUT_DIR`：输出根目录，见第 5 节。

## 3. 库接口

```ts
import { ServiceSession } from 'mmd2vsdx/service';

const session = new ServiceSession({ outputDir: 'D:/work/vsdx', cwd: process.cwd() });
try {
  const r = await session.convert({ text: 'flowchart LR\n  A-->B' });
  console.log(r.path, r.sha256);
} finally {
  await session.shutdown();   // 长驻进程退出前必调，关掉浏览器
}
```

### 3.1 构造

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `outputDir` | `string?` | 输出根目录；缺省取环境变量 `MMD2VSDX_OUTPUT_DIR`，都没有则只用工作目录 |
| `cwd` | `string?` | 工作目录，默认 `process.cwd()`；相对路径按它解析，它也是一个允许写入根 |

### 3.2 方法

| 方法 | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `convert(req)` | `{ text, path?, overwrite? }` | `Promise<ConvertReceipt>` | 单次转换并落盘；失败抛 `ServiceError` |
| `convertMany(items, outDir?, overwrite?)` | `items: { text?, file?, name? }[]` | `Promise<BatchReceipt>` | 逐项隔离失败，不因单项失败中止 |
| `validate(text)` | `string` | `ValidateReceipt` | **同步**，只解析不落盘；**失败也返回回执，不抛** |
| `inspect(file)` | `string` | `InspectReceipt` | **同步**，读自产 `.vsdx`；失败抛 `ServiceError` |
| `shutdown()` | — | `Promise<void>` | 关浏览器；可重复调用 |

`validate` 与 `inspect` 是同步方法（不开浏览器），不要写成 `await`；`convert`
与 `convertMany` 才走渲染，必须 `await`。会话的并发与生命周期见第 9 节。

## 4. 回执结构

### 4.1 ConvertReceipt

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `path` | `string` | 产物绝对路径 |
| `bytes` | `number` | 字节数 |
| `sha256` | `string` | 内容哈希；同输入两次转换一致，可用于比对 |
| `kind` | `string` | 图型：`flowchart`、`block`、`class`、`er`、`sequence` |
| `pageSize` | `{ widthIn, heightIn }` | 页面尺寸（英寸），等于内容外包围框加两倍半线宽 |
| `shapeCount` | `number` | 页面内形状总数 |
| `warnings` | `string[]` | 不阻断的提示，例如没有官方母版的构造型 |

### 4.2 ValidateReceipt

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | `boolean` | 解析是否通过 |
| `kind` | `string?` | 通过时的图型 |
| `supported` | `boolean` | 该图型是否被支持；不支持时为 `false` |
| `counts` | `Record<string, number>` | 元素计数：`shapes`、`edges`、`clusters`，以及图型专属块 |
| `error` | `{ code, message, hint? }?` | 失败时的错误信息 |

### 4.3 BatchReceipt

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `outDir` | `string` | 实际输出目录（绝对路径） |
| `total` / `succeeded` / `failed` | `number` | 汇总计数 |
| `results` | `BatchItemResult[]` | 逐项结果，顺序与入参一致 |

`BatchItemResult`：`{ index, ok, path?, kind?, bytes?, sha256?, error? }`。
`BatchItem` 三选一：`text`（内联文本）、`file`（输入文件，相对 `cwd`），`name`（可选输出文件名）；
都不给或都为空时报 `invalid_argument`。

### 4.4 InspectReceipt

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `path` / `bytes` | `string` / `number` | 被检视的文件与大小 |
| `parts` | `{ uri, contentType, bytes }[]` | 包内部件清单 |
| `pages` | `{ name, widthIn, heightIn }[]` | 页面名与尺寸 |
| `shapeCount` | `number` | 形状总数 |
| `texts` | `string[]` | 页面文本，去重后最多 100 条 |

## 5. 路径与覆盖规则

1. **允许根** = `outputDir`（或 `MMD2VSDX_OUTPUT_DIR`）加 `cwd`；两者都不设时只有 `cwd`；
2. **输出三级回退**：方法参数 `path` 或 `outDir` → 配置的输出根目录 → `<cwd>/vsdx-output/`；
3. 目标路径先 realpath 归一（Windows 下大小写归一），越界一律拒绝；
4. **默认不覆盖**：目标已存在且未传 `overwrite` 时抛 `path_denied`；
5. 落盘是原子写：先写临时文件再改名，不会留半写产物。

## 6. 错误契约

失败时抛 `ServiceError`（库）或输出 `{ ok: false, error }`（命令行），都带 `code`、`message`、`hint`。

| code | 触发条件 | 调用方建议动作 |
| --- | --- | --- |
| `unsupported_kind` | 输入的图型不在五类支持清单内 | 换图型；支持清单见 `hint` |
| `parse_error` | mermaid 语法错误或空输入 | 先用 `validate` 定位，再修文本 |
| `path_denied` | 路径越界、目标已存在且未允许覆盖、目录不可写 | 换路径，或传 `overwrite: true` |
| `too_large` | 输入超过 256KB、产物超过 8MB、批量超过 50 项 | 拆小输入或分批调用 |
| `invalid_argument` | 参数错误：批量空、字段缺失、文件读不到、包不可解析 | 修调用参数 |
| `renderer_unavailable` | 浏览器起不来（未装 Chromium、缺系统依赖） | 执行 `npx playwright install chromium` |
| `internal` | 其它未归类错误 | 把 `message` 连同复现输入反馈 |

上限常量可直接引用：`kMaxInputBytes`（256KB）、`kMaxOutputBytes`（8MB）、`kMaxBatchItems`（50）。

## 7. 命令行协议

```
mmd2vsdx convert <文件|-> [--out 路径] [--overwrite]
mmd2vsdx validate <文件|->
mmd2vsdx batch <目录|文件...> [--out 目录] [--overwrite]
mmd2vsdx inspect <文件.vsdx>
mmd2vsdx -h | --help
```

- 相对路径按**当前工作目录**解析；`-` 表示从 stdin 读入 mermaid 文本；
- `batch` 的目录参数只收 `.mmd` 文件，按文件名字典序处理；
- **stdout 只有一份 JSON**（每行一条，便于流式解析），各子命令的形状：
  | 子命令 | 成功 | 失败 |
  | --- | --- | --- |
  | `convert` | `{ ok: true, ...ConvertReceipt }` | `{ ok: false, error }` |
  | `inspect` | `{ ok: true, ...InspectReceipt }` | `{ ok: false, error }` |
  | `validate` | `ValidateReceipt`（自带 `ok`，`ok: false` 时含 `error`） | 同左，`ok: false` |
  | `batch` | `{ ...BatchReceipt, ok }`，`ok = failed === 0` | 同左（逐项错误在 `results[].error`） |
- **stderr 是人类可读的一行摘要**，不要拿去做解析；
- 退出码：`0` 成功；`1` 处理失败（含批量中任一项失败，以及 `validate` 的 `ok: false`）；`2` 用法错误。

示例：

```bash
# 转换并把回执交给下游解析
mmd2vsdx convert ./docs/flow.mmd --out ./out/flow.vsdx | jq -r .sha256

# 批量：产物名 = 输入名，落在指定目录
mmd2vsdx batch ./mmd --out ./out --overwrite
```

```ts
// Node 里把 CLI 当子进程用（跨语言场景同理）
import { execFile } from 'node:child_process';
import { promisify } from 'node:util';
const run = promisify(execFile);
const { stdout } = await run(process.execPath, ['bin/mmd2vsdx.mjs', 'convert', '-', '--out', 'out.vsdx'], {
  input: 'flowchart LR\n  A-->B',
});
const receipt = JSON.parse(stdout);
if (!receipt.ok) throw new Error(`${receipt.error.code}: ${receipt.error.message}`);
```

## 8. 稳定性与兼容

- **承诺稳定**：`mmd2vsdx/service` 的导出、方法签名、回执字段、错误码、命令行参数与退出码；
- **不承诺**：包根的四步管线 API、`dist/` 内部目录结构、产物的 XML 细节与母版命名；
- **确定性**：同一输入两次转换字节一致（`sha256` 可比对），批量与单次走同一实现；
- **变更登记**：alpha 期的破坏性变更升 `alphaN` 并在此列出；当前 `0.1.0-alpha3`。

## 9. 集成与部署要点

### 9.1 运行模型

- **一个 `ServiceSession` 就是一个 Chromium**：会话内渲染串行排队，同一会话的并发调用
  不会并行执行；要并行就开多个会话，代价是多个浏览器进程（内存按份数增长）；
- **退出前必须 `shutdown()`**：不调用则浏览器常驻、进程可能不退出。长驻宿主
  （Electron 主进程、服务进程）在退出钩子里调一次；一次性脚本用 `try/finally`；
- 渲染失败时会重建页面重试一次，再失败才抛 `renderer_unavailable` 或 `parse_error`。

### 9.2 Chromium 从哪来

渲染 mermaid 依赖 Playwright 的 Chromium，默认装在用户缓存目录（Windows 为
`%LOCALAPPDATA%\ms-playwright`），装过一次全机共用。三种口径：

| 场景 | 做法 |
| --- | --- |
| 开发机 | `npx playwright install chromium` 装一次即可 |
| 打包分发、离线可用 | `PLAYWRIGHT_BROWSERS_PATH=0 npx playwright install chromium`，浏览器落进依赖目录，随产物一起打包 |
| 复用宿主自带的 Chromium | 当前**不支持**，见 9.4 |

### 9.3 版本与依赖形态

- 包是 `private: true`，**未发布 npm**；集成按 tarball 或 git 依赖锁版本（见第 2 节），
  建议锁到 tag（当前 `v0.1-alpha3`）而不是跟随分支；
- tarball 自带 `dist/`，安装时不跑构建，适合 CI 与打包链；git 依赖会执行 `prepare`
  构建，需要 devDependencies 与网络，打包链里不推荐；
- Node 22.2 以上；同进程集成时以宿主的 Node 版本为准。

### 9.4 当前不提供

- HTTP / 远程服务与 MCP（见 `待讨论功能备忘.md` P-5）；
- 由宿主注入浏览器实例、或指定 Chromium 可执行文件的位置；
- 流式与增量输出、多浏览器池、渲染进度回调。

## 读法

- 想先看懂整体：`00-一览.md` + `diagrams/工作流程图.mmd`；
- 想看现状（模块边界/数据流/验收）：`现状-*.md`；
- 想看类的关系：`diagrams/类图.mmd`；
- 想做某一个包：按对应层级打开文档，每篇固定五节：
  职能 → 目录与文件 → 类与职责 → 函数表 → 边界与注意；
- 实现顺序：契约层 → 解析层 → 转义层（先公用库再图型包）→ 打包层。

## 决策记录（当前已定）

- 2026-09 模块结构按流水线划分：解析 → 中间态 json → 图型模块 → xml 部件 → 压缩；
- **所有包平级、互不嵌套**；图型每类一包、互不合并；通用包含
  flowchart/state/c4/block，timeline/xy 暂走通用骨架兜底；
- **设计不被现有代码约束**：按本目录从零实现，旧代码只作行为参照与
  资产来源，不做文件级迁移（见 06 文档）；
- 两个契约层：契约 A（图型 json）、契约 B（部件清单 uri+contentType+xml）；
- 压缩库只懂 OPC/ZIP；图型包不碰 zip、parser 不写 xml 部件；
- 详细设计遵循面向对象思想：每包先列类与职责，再列文件与函数；
- 先定契约与结构，再动代码；每包独立封包单测。

# 契约 B：部件清单

> 契约 B 是图型包的唯一输出、压缩库的唯一输入：一份"完整的 vsdx 内容"。
> 结构就是部件数组，与 OPC 包一一对应；`squeeze` 拿到它就等于拿到成品。

## 1. 模块职能

契约 B 让"画图"与"打包"彻底分开：图型包产出部件数据，不碰 zip；
压缩库只认数组，不认 Visio 语义。校验保证任意两份契约 B 可以互换下游。

## 2. 目录与文件

```
src/contracts/
└── b.ts          契约 B 类型 + 默认工厂 + 校验 + 工具
```

## 3. 类型定义

```
XmlPart {
  uri: string;           // 规范部件 URI（'/visio/pages/page1.xml'）
  contentType: string;   // 部件媒体类型（'application/vnd.ms-visio.page+xml'）
  xml: string;           // 部件 XML 文本（含声明行）
}

ContractB {
  parts: XmlPart[];      // 全部部件（含页面、母版、文档、属性、登记表）
}
```

约定：

- `parts` 顺序即打包顺序，先登记表后内容，压缩库不重排；
- uri 必须唯一，部件间引用靠 uri 相对关系；
- docProps、[Content_Types].xml、_rels/.rels 由 xml-parts 组装时补齐，
  图型包只见页面与母版相关部件。

## 4. 关键函数

| 函数名 | 输入 | 输出 | 作用描述 |
| --- | --- | --- | --- |
| part(uri, contentType, xml) | 三要素 | XmlPart | 部件构造工厂 |
| validateContractB(b) | 契约 B | {ok, errors[]} | uri 唯一性、contentType 与 uri 匹配表 |
| addPart(b, part) | 契约 B + 部件 | 新契约 B | 追加部件，重复 uri 抛错 |
| mergeParts(a, b) | 两份契约 B | 契约 B | 图型包把母版/文档部件并入页面部件 |

## 5. 边界与注意

- 图型包默认产出三类部件：页面（pages.xml/pageN.xml/rels）、母版（masters/
  下三件）、文档基座（document.xml/windows.xml）；其余部件由 xml-parts
  统一补齐（docProps、登记表、包级关系表）；
- xml 文本必须完整可解析：图型包产出前经 `xml-parts.validate` 校验；
- 待核：页面级 rels（page1.xml.rels）在自产样本中可省，组装期按是否
  启用母版引用决定是否生成，见 research c4-1 篇 W-4。

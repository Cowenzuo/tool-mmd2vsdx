# 01 设计体例与约定

> 本文件是全部详细设计的入口：先给包总览树与数据流，再定 OOP 设计约定
> 与每篇文档的体例。各包设计的正文以本文件的约定为准。
> 设计原则：**从格式认知出发**（docs/research 是唯一事实依据），不背
> 现状代码的包袱；即使推翻重做也按本结构来。

## 一、包总览目录树

```
src/
├── contracts/     契约 A、B（纯类型，任何包都可读，不可写）
├── parser/        ① mmd-parser：文本 → 契约 A
├── diag/common/   ② 通用（flowchart/state/c4/block/timeline/xy）
├── diag/class/    ③
├── diag/er/       ④
├── diag/gantt/    ⑤
├── diag/sequence/ ⑥
├── diag/git/      ⑦
├── diag/pie/      ⑧
├── diag/quadrant/ ⑨
├── diag/mindmap/  ⑩
├── common/        ⑪ 公用库（被 ②-⑩ 依赖）
├── xml-parts/     ⑬ 部件栈（契约 B 校验与组装）
├── squeeze/       ⑭ 压缩库（契约 B → .vsdx）
├── xml/           自研 XML 栈（树/解析/序列化；底层库，无业务）
├── opc/           自研 OPC/ZIP 底层（条目/关系/登记表；底层库，无业务）
└── app/·cli.ts    编排与入口（parser → diag-* → xml-parts → squeeze）
```

包间依赖只允许四条边：`diag-* → common`、`diag-* → contracts`、
`parser → contracts`、`xml-parts/squeeze → contracts`。
包装层（xml/opc）被所有上层消费但不含任何业务语义。

## 二、数据流

```
mermaid 文本
  parser.convertText(text) ──► 契约A（按 A.kind 分派图型包）
  diag-* .render(A) ──► 契约B（parts 数组）
  xml-parts.assemble(parts) ──► 校验后的部件清单
  squeeze.pack(parts) ──► Buffer（.vsdx 字节）
```

## 三、OOP 设计约定

1. 每包一个门面类（`XxxRenderer` / `CommonKit` / `Squeeze`），对外只有
   一个入口方法，包内结构包内自理；
2. 类按职责命名：布局器（Layout，只算位置）、写手（Writer，只拼 XML
   片段）、引擎（Engine，编排布局与写手）、服务（Service，无状态能力）；
3. 纯数据用 interface + 默认工厂，不携带方法；有状态对象单例化、包内私有；
4. 类与函数的依赖方向：引擎 → 布局器 → 写手 → common 零件；
   抽象可替换的位置（母版客户端、样式解析器）定义接口；
5. 每个可单测的纯函数：输入是契约或纯数据，输出是纯数据或树节点，
   不读文件、不开浏览器、不进全局。

## 四、详细设计体例（每包一致，借鉴 research 五步法）

| 节 | 内容 | 对应 research 体例 |
| --- | --- | --- |
| X.1 模块职能 | 包在管线里的位置、输入输出、一句话职责 | 文件定位 |
| X.2 目录与文件 | 包内目录树，每个文件一句话 | 实例内容 |
| X.3 类与职责 | 类名 / 一句话职责 / 关键方法签名 | 字段解释 |
| X.4 函数表 | 函数名 | 输入 | 输出 | 作用描述 | 字段扩展 |
| X.5 边界与注意 | 不做的事、依赖限制、待核点 | 补充注解 |

函数表统一四列：**函数名 | 输入 | 输出 | 作用描述**。类型名以
`contracts/` 里的定义为准，行文用 `契约A.xxx` / `契约B.xxx` 指代。

## 五、命名约定

- 包目录小写连字符：`diag/gantt`、`xml-parts`；
- 类名首字母大写驼峰，文件名小写驼峰不带分隔符（`masterAssets.ts`）；
- 入口文件统一 `index.ts`，包内私有模块不以 index 提供；
- 函数动词开头：`buildXxx` 造部件、`renderXxx` 造页面、`writeXxx` 写片段。

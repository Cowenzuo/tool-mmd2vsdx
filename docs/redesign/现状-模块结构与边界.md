# 00 模块结构与边界

> 本文件描述 `source/` 重做后的分层与依赖；白名单的可执行化守门脚本
> （`temp/check-architecture.mjs`，开发期工具不入库）与本文一致（违反即 exit 1）。
> 分层图见 `diagrams/arch-overview.mmd`。

## 一、分层总览（自底向上）

```
L0 契约层   contracts      —— 契约 A（图型 json）与契约 B（部件清单）类型定义，零依赖
L1 包层     opc             —— ZIP/部件 URI/内容类型/关系/包
L2 公用库   common          —— xml（树/序列化/常量）+ 意图/几何/公式/文本/单元/样式/母版/端口等写手
L3 解析层   parser          —— Chromium + mermaid 库 → 快照 → 归一化 → 契约 A
L4 转义层   diag            —— 一目录九文件：common/pie/quadrant/git/sequence/
                              mindmap/class/er/gantt（每图型一文件，平级互不 import）
L5 打包层   xml-parts（部件组装）   squeeze（OPC/ZIP 压缩）
L6 编排层   convert.ts      —— 契约 A → 分派 → 契约 B；无人依赖本层
```

`common` 稍高于契约：形状/母版/样式写手以 `XmlPart` 为输出，允许依赖
`contracts`（xml 树/常量并入 common，不再单独成层）；各层只能依赖更下层。

## 二、分组与实测依赖边

分组 = `source/` 顶层目录一组；同组互引放行。跨组白名单（目标 ← 源）：

```
convert    -> contracts, common, opc, parser, diag, xml-parts, squeeze
parser     -> contracts, common
diag       -> contracts, common
xml-parts  -> contracts, common, opc
squeeze    -> contracts, opc
opc        -> common
common     -> contracts
```

实测：49 个源文件（不含测试）、93 条跨组边，与上表完全一致，无任何越层或反向边。

## 三、要点与边界

1. **转义层一目录九文件**：diag/ 下每个图型一个 .ts（平级、互不 import）；
   新增图型 = 新增 `diag/<kind>.ts` + 在 `convert.ts` 加一行分派，不动其它文件。
2. **图型每类一文件，互不合并**：契约 A 以 kind 判别，语义块各自独立
   （classModel/erModel/gantt/sequence/git/pie/quadrant/mindmap 等）。
3. **压缩库独立，只懂 OPC/ZIP**：`squeeze` 不认识图型；`opc` 不懂业务。
4. **契约是唯一边界**：parser 只产出契约 A，diag 包只消费契约 A 产出契约 B；
   A 与 B 之间不存在其它共享数据结构。
5. **测试文件不参与红线**：`*.test.ts` 走门面组合（如 spec 测试装配
   Parser → renderContract → PartsAssembler → Squeeze），不属于分层义务。

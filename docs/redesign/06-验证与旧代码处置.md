# 17 附录：验证与旧代码处置

> 本附录回答两件事：新设计怎么验收、现有代码怎么处置。
> 结论先行：**新设计不背现有代码的包袱**——按 00-16 文档从零实现，
> 现有代码只做两件事：提供资产数据；作为行为参照物接受 golden 对比。

## 1. 验证项（每包实现完即跑）

| 项 | 手段 | 通过标准 |
| --- | --- | --- |
| 结构契约 | 契约单测（parser 测 json、diag 测部件、squeeze 测字节） | 全部通过 |
| 产物等价 | 16 样本 golden 对比（解析产物解包后逐部件结构比对） | 全绿，diff 非零即停 |
| 类型 | `npm run typecheck` | 零错误 |
| 依赖边 | 结构检查脚本按 01 定义的依赖规则 | 只有契约与 common 边 |

## 2. 旧代码的三种去向（已执行）

| 类别 | 旧位置 | 处置 |
| --- | --- | --- |
| 行为参照 | `src/` 现行实现 | 不迁入新包；重构完成并稳定后已移除（随 git 历史保留） |
| 资产数据 | `resources/visio-*`、提取出的 stencil 记录 | 迁移到新结构的数据目录，这是唯一"必须带走"的现状物 |
| 测试夹具 | `resources/test-examples/`（mmd 源稿） | 保留，作为验收输入；结果产物 `vsdx-output/` 只由新管线产出 |

## 3. 边界与注意

- 本附录不规定新代码从哪里"搬"什么；新包的类与函数以 00-16 设计为准，
  不要求与旧实现一一对应；
- golden 基线是唯一的行为锚点：新实现先保证产物等价，再做功能增强；
- 旧代码的文档（docs/architecture/）在重构完成后改写为"新结构现状"。

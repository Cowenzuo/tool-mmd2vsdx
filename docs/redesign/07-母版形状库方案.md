# 07 母版形状库方案（class / ER / sequence 母版实例化）

> ⚠ 支持范围（2026-09 收敛）：gantt 图型已移除支持，本文中 gantt 相关段落为历史方案记录。

> 本文件是本次整改的**先行方案**（只定方案、不动代码）。问题陈述见文首；
> 实施按第 7 节里程碑逐层推进，每步可验收。正文引用均为实测数据或源码行。

## 00. 准则（硬性，用户定调——先于一切取舍）

1. **唯一事实源**：用户提供的模板解压包
   `docs/research/标准研究模板-手动创建vsdx并解压/{class,ER,sequence}/`（gantt 已随图型收敛）。
   母版内容（masterN.xml）、目录条目（masters.xml 属性）、**页面实例模式**
   （page1.xml 中每个 `Master=` 引用的实例 cells / 嵌套 `MasterShape=` 覆写）、
   Connects、rels 一律以其为准，逐字节可 diff。
2. **零自定义规避**：禁止下列任何一类做法——
   - 自造公式/结构（无模板实证的 F=、Section、Row 组合）；
   - 把母版行为"下放"到实例（母版承载的行为组/几何/公式必须留在母版）；
   - 把官方 Group/复合结构"摊平"成自绘形状冒充；
   - 用非官方形状（如临时矩形/连线）代替缺失的官方母版；
   - 用自定义数据段/自定义字段补足模板未覆盖的语义。
3. **未覆盖即显式暴露**：模板包未涵盖的图型语义（如 class 模板只有 3 类关系母版、
   sequence 只有 Loop/Opt 片段、lifeline 行规模与实例高度不符等），一律
   **记录为"待核/待素材"清单**——显式报不支持或列入待办，绝不用自定义方案填坑。
4. **母版化是唯一验收路径**：spec 新增断言强制 `Master=` 引用角色齐全；
   自足式分支仅作"母版目录缺失"时的防御兜底（防死图），永远不构成通过路径。
5. **实例模式 = 官方保存态**：连接线几何实例化、文本柄缓存等"实例怎么写"的
   细节，均以对应素材基本样本（basic-5/6）与专篇为据照抄，不自行发挥。

## 0. 问题陈述（实测证据）

现状：**只有通用路径（flowchart/state/block/c4/timeline/xy）真正使用母版**；
五个专用图型（class/ER/gantt/sequence/mindmap）的产物 XML **零母版引用**，
全部为自绘"自足式"形状（Group + 嵌套子形状，行为公式直接写实例）。

实测（本工程产物 `page1.xml`，`<Shape ... Master="N">` 计数）：

| 样本 | 图型 | 产物 Master 引用 | 产物母版文件数 |
| --- | --- | --- | --- |
| 05-flowchart-1 / 16-state-1 | common（母版实例化） | ✅ 7 / 9 处（ID 100–102） | 2–3 枚（按需打包） |
| 03-class-1 | class | ❌ 0 处 | 1 枚（Rectangle 骨架） |
| 04-er-1 | er | ❌ 0 处 | 1 枚 |
| 07-gantt-1 | gantt | ❌ 0 处 | 1 枚 |
| 15-sequence-1 | sequence | ❌ 0 处 | 1 枚 |
| 11-mindmap-1 | mindmap | ❌ 0 处 | 1 枚 |

对照官方基准（`docs/research/标准研究模板-手动创建vsdx并解压/`，单/双引号均统计）：

| 素材 | 官方 Master 引用 | 官方母版文件 |
| --- | --- | --- |
| class | 27 处 | 12 枚（页面用 8 枚） |
| ER | 17 处 | 8 枚（页面用 5 枚） |
| gantt | 65 处 | 13 枚（页面用 10 枚） |
| sequence | 15 处 | 12 枚（页面用 9 枚） |

根因（源码）：

- `source/convert.ts` 对专用图型先塞 `packSkeletonMasters(catalog)`——
  只打包 `kSkeletonMasterName = 'Rectangle'` 一枚，注释原文：
  "专用包母版骨架：未引用母版，仅为满足 research 6.1.4 的『两支目录恒有』"；
- `ClassRenderer/ErRenderer/GanttRenderer/SeqRenderer/MindmapRenderer` 自绘 XML，从不写 `Master=`；
- `source/common/masters/templates.ts` 只有 6 枚模板（节点 5 种 + Dynamic connector），
  全部属于 basic/flowchart 家族——**专用图型所需的官方母版从未入列**。

为何"16 样本全绿"掩盖了问题：`tests/spec.test.ts` 检查口径不对称——

- `common`：明确断言 `Master=` 必须存在；
- `class/er/gantt/sequence`：只断言**自绘结构**（Group 容器、成员公式 LISTSHEETREF、
  100 行时间格、Field 段、pr 样式家族），**从不要求 `Master=`**；
- `mindmap/git/pie/quadrant`：`noSpec`，仅 L1 骨架 + 形状数下限。

即：测试是为"自足式模仿官方结构"量身定制的，母版实现与否不在检查范围内。

## 1. 目标

对五个专用图型建立对应官方母版形状库，产物改为**母版实例**：

```
mermaid → 契约 A → 专用渲染器（Master="N" 最小实例 + 差异 cell）
                  → MasterPacker 按需打包母版三件套（ID 从 100 起）
                  → 页面 Shape 引用母版，行为公式由母版承载
```

- 每类图所需的母版**名称清单**、内容、MasterType 与官方提取物逐字一致；
- 页面实例写法按官方样本的"最小实例模式"逐母版套用（第 5 节）；
- 保留现有自足式实现作为**兜底分支**（无目录/母版未收录时，策略与 common 相同：
  `masterId > 0` 才引用），保证目录缺料时产物仍可打开；
- 验收升级：spec 对每类新增"母版引用角色齐全"断言（第 6 节）。

## 3. 资产来源与合规

**提取实施事实（已实测）**：
- 素材文件本身为合法 UTF-8，但 `masters.xml` 条目的 `Name`/`Prompt` 属性为
  **乱码文本**（GBK 时段→UTF-8 时未正确转码，如"矩形"显示为"鐭╁舰"）；
  `NameU` 全部为 ASCII 且可靠——提取一律以 `NameU` 为准，`Name` 合成 `=NameU`
  （与现有 6 枚模板同策），`Prompt`/`Icon`（base64）不携带（装饰性，见 D2）；
- 条目 ID（7–16 等）与内容文件名**无关**：`Rel r:id` → `masters.xml.rels` →
  Target 才是内容文件，提取脚本必须走这条映射；
- 内容文件（masterN.xml）为 `<MasterContents>` 整体，单引号风格；
  存储时**原文保留**（不做引号改写），等价性测试用 XML 规范化后比对（解析再序列化）。

- 素材只读；提取一次性脚本放 `temp/`（如 `temp/audit/gen-type-templates.mjs`，
  仿照旧 gen-templates.mjs），按 `masters.xml.rels` 映射逐枚输出；
- 输出格式与现有 `templates.ts` 一致（双引号、UTF-8、MasterContents 原文），
  便于 diff；建议新增**内容等价单测**（模板字符串 vs 素材原文逐字节比对，防漂移）；
- 合规沿用既定红线：**官方 vssx 不入库**；母版内容以"程序化模板"形式固化源码
  （现 6 枚已是此策）。新增约 560KB 源码内容，属同策的量变化，
  建议在 README 合规段明示规模（决策点 D4）。

## 5. 渲染器改造（专用包：自足式 → 母版实例）

官方样本的实例写法已实证：`<Shape Master='N'>` + 实例差异 cells + 文本 +
**嵌套 `MasterShape=` 子形状覆写**（类盒内部成员槽）。各包的实例模式逐母版
从素材 `page1.xml` 摘录为"实例模式表"（实施时先补表再写码），要点：

- **class**：类盒/接口/枚举实例 = Pin/Width/Height + `Relationships=SUM(DEPENDSON(...))`
  引用成员/分隔线 + `User.WidthMin/EntityName` + `Control.Row_1` + Connection 行
  `F=Inh` + Text + 嵌套成员槽覆写；Member/Separator 顶层实例（`F=LISTSHEETREF()!...`
  公式族、`ShapeFixedCode`、`TxtWidth F=Inh`）；关系三母版实例（Begin/End + 触发器 +
  端点粘附 Connects），箭头样式由母版承载（EndArrow 12/14 等）；
- **er**：实体容器（含 User 注册行 msvShapeCategories（母版已载，实例按需覆写））+
  属性行（PrimaryKey=1/0 区分走母版版本）＋分隔线＋关系线（命名连接行 User.RelationshipName）；
- **gantt**：frame/Column/标尺格（Field 段数据源按实例补）/Row/Task bar（8 子形状
  1301 cells 全在母版，实例只写位置尺寸差异——**宁可少覆盖，不可乱覆盖**）/
  Text Entry/Milestone/Link lines（实例化几何+命名连接行）；
- **sequence**：Object/Actor lifeline（实例 Pin/宽高 + 时间格行数随高度；行规模
  修正在 normalize 落点）、Activation（1-D 锁高）、消息四类（MasterType=29）、
  片段框（Loop/Optional）＋消息端点 ToPart 扩到时间格（100+ 行号）；
- 所有实例保留现坐标/尺寸覆盖逻辑（母版占位尺寸远大于 mermaid 布局，
  防重叠）；`masterId === 0`（目录缺失）时走现有自足式分支，行为不变。

**实测速记（已直接核验的官方实例模式，实施时逐条落实）**：
- class 关系线：**三种关系实例模式已全量取证**——Dependency / Interface Realization
  为**双端 PAR 钉接**（`BeginX/Y=F=PAR(PNT(Sheet.N!Connections.Xn,..))`、
  `EndX/Y` 同理）；Inheritance 为 **Begin PAR + End `_WALKGLUE` + `ConFixedCode=5`**；
  三者的公共面：`PinX/PinY/LocPinX/LocPinY F=Inh`、`Width/Height F=GUARD(...)`、
  `LayerMember=0`、`BegTrigger/EndTrigger V=2{_XFTRIGGER(Sheet.N!EventXFMod)}`、
  `TxtPinX/Y + TxtHeight/TxtLocPinY F=Inh`、`Control.TextPosition` 与 User 行
  （关系名/箭头差值/角度缓存）；
  **EndArrow 由母版承载（官方实例不写 EndArrow）**——现渲染器把 EndArrow 12/14
  写实例、触发器 V=1 无公式，均为**明确偏差**，列入整改销毁项；
  端点粘附 Connects：PAR 端 `ToPart=100+行号`（Connections.Xn），
  WALKGLUE 端 `ToCell=PinX/PinY ToPart=3`（basic-5 本体粘附同规）；
- class 成员行（Master='8' 实例）：`LocPinX/TxtWidth F=Inh`、`Width F=LISTSHEETREF 家族`、
  `Relationships=SUM(DEPENDSON(5,Sheet.N!SheetRef()))`、`ShapeFixedCode=1`、
  **`NoLine=1{Inh}`（成员行不描边）**、User 行名
  `MemberName/ContainerMargin/WidthMin/BackFillColor/BackLineColor/LockAspect...`
  （现代码用 `${member}` 做行名——**明确偏差**，列入整改销毁项）；
- ER 属性行实例：Primary Key Attribute 带 **`ObjType=1`**、`Value=1{Inh}`（PrimaryKey），
  Attribute 行带 `Value=3/4{Inh}`（行类型代号）、颜色/字号行族——实施时取官方数值表，
  不得自拟代号；ER 实体/属性行互指公式均 LISTSHEETREF 家族，与 class 同源；
- gantt Task bar 实例：`PinX F=MIN(MAX(User.ScaledStartPos+LocPinX,User.ScaleStart),User.ScaleEnd)`、
  `PinY F=Sheet.N!PinY`（钉行）、`Width F=User.ScaledDuration-(LeftWidthReduction+RightWidthReduction)`、
  `Height F=Sheet.N!Height`、`LayerMember=1`、`Comment`、User 行族（LeftText/RightText/
  InnerText/ScaledStartPos/ScaledEndPos/StartSymType=9/EndSymType=9/**GCVisioGUID/
  GCModelGUID/GCChartGUID** 数据联动三 GUID 行）、Property 段——GUID 为官方保存态
  必需项，UUID 生成属官方逻辑，不属"自定义"；
- sequence 生命线实例：`PinX/PinY + Control.Row_1(Y)` + Connection 行（**用到的**时间格
  行号，`Y` 缓存 `F=Inh`；行号从 IX≈14 起、用完即止，超出段 V=-6.35 封顶）——
  母版承载 100 行定义与公式；实例不重复 100 行，与素材保存态一致；
- sequence 消息/激活实例：均为**双端 PAR 钉接**（`BeginX/Y=F=PAR(PNT(Sheet.N!Connections.Xk,...))`
  到生命线时间格行、`EndX/Y` 同理），非 WALKGLUE；触发器 `_XFTRIGGER(Sheet.N!EventXFMod)`；
  激活条 `Width=1MM/0.5MM F=Inh` + Connection 行；片段实例仅 `PinX/PinY` + 嵌套
  `MasterShape=` 覆写（Group 母版）；
- ER 实体实例：`PinX/PinY/Height`（**不写 Width**）+ `Relationships=SUM(DEPENDSON(...))`
  + `TxtPinY F=Inh` + `User.WidthMin` + `Control.Row_1(Y/YDyn F=Inh)` + Connection 行
  （IX0/1/3，Y F=Inh）+ 嵌套 `MasterShape=` 覆写（II 段 IX3/4）——与 class 类盒同为
  Group-容器-成员模式，差异在行数与 User 行名；
- **D5 已实锤**：验收样本 `03-class-1.mmd` 含 `--o`（聚合）与 `-->`（关联），
  素材包关系母版仅 3 类（Dependency/Interface Realization/Inheritance）——
  按准则 3 记为"待核/待素材"缺口，不映射不自定义；至少需官方 UML 模具的
  Association/Aggregation 母版提取物才能闭环。

2. **实例模式抽查（新增）**：class Relationships DEPENDSON、member LISTSHEETREF、
   sequence 消息 ToPart>103 等（沿用现有断言但改为"母版承载"口径）；
3. **旧断言重写**：现 class/er/gantt/sequence 的 L2 大量断言"实例自携"行为 cells
   （如 class 组 ObjType/LockWidth/ShapePlaceStyle 在实例）——母版实例化后这些
   走母版，断言必须改为"实例或母版"（同 common 现有 `masterXmls.some(...)` 写法）；
4. **内容等价单测（新增）**：模板字符串 vs 素材原文逐字节一致；
5. **兜底分支仅防御**：catalog=null（自足式）路径保留但**不作为验收路径**
   （spec 强制 Master= 引用），仅防母版目录缺失时产物变死图；切换后保留一个最小兜底用例；
6. 手检：建议人工在装 Visio 的机器打开产物抽查（类盒成员拖拽/连接线走线/
   gantt 任务条缩放），与解压断言互补（见 D7）。

## 8. 决策点与风险

| # | 项 | 建议 | 说明 |
| --- | --- | --- | --- |
| D1 | mindmap 素材 | M0 前置或在 M6 时再启动 | 需要 Visio 手工样本；无素材不可施工 |
| D2 | 官方条目属性 | 采用官方原文（MasterType 等保真） | Icon（base64）可剥离降体积；缺 Icon 不影响页面渲染 |
| D3 | 母版内容存储 | 分文件 TS 模块 | 与现状一致、零运行 IO；单文件 600KB+ 不可取 |
| D4 | 合规规模 | README 明示"约 560KB 官方内容固化" | 与既有 6 枚同策，量变非质变；如收紧则需另行决策 |
| D5 | 关系语义缺口 | class 素材仅 3 类关系母版；Association 等 mermaid 语义无可对应官方母版 | **不映射、不自定义**：未覆盖关系类型显式报错并列入待核清单（补素材后再实现），见准则 3 |
| D6 | 模板未覆盖情形 | sequence lifeline 行规模、gantt 标尺公式链，素材仅覆盖单一尺寸 | 照模板实现（母版固定行为照抄）；与模板不符处记入"待核清单"，不发明（准则 2/3） |
| D7 | 真机验证 | 有 Visio 的机器人工抽查 | 解压断言不能覆盖"打开后行为"（公式重算/拖拽） |
| 风险 | Task bar/Milestone 81–84KB 公式密集 | 实例覆盖严格按官方模式清单 | 覆盖错误会导致打开异常，宁缺毋滥；每步留自足式兜底 |

# 开发过程 —— 现役设计

> 名字还叫"开发过程"，里面装的是**当前**的结构与口径：系统现在什么样、为什么这样、
> 边界与红线在哪。
>
> **过程记录不留**：当初怎么发现问题、哪一轮改的、验收了什么，这些从 git 历史里查。
> 留旧的对照没有意义，只会让人分不清哪一版还算数。

## 怎么读

- 想知道系统分几层、各包管什么、红线在哪 → [01-结构设计.md](01-结构设计.md)；
- 想知道一次转换数据怎么流、各类图型从哪提取、画布怎么算 → [02-数据流与画布.md](02-数据流与画布.md)；
- 想知道对齐官方模板的准则、仍成立的取舍、还没取证的条目 → [03-对齐准则与取舍.md](03-对齐准则与取舍.md)；
- 想知道 Visio 产物内部到底怎么写 → 去 `docs/VSDX解压结构研究/`，那边是唯一事实源，这里只指过去；
- 想动手改代码 → 先看 `docs/AI开发约定/项目特定规范.md` 的红线与验收口径。

## 边界

- 文档写的是**当前状态**：改了代码就改文档，不留"上一版怎么写"的对照；
- 实现的唯一真相是 `source/` 下的代码，文件清单、函数签名这类细节以代码为准，
  本文档区只写机制与约定；
- 对外契约的正文在 [docs/接口协议.md](../接口协议.md)，Visio 内部结构的正文在
  `docs/VSDX解压结构研究/`，两边都不在这里重复；
- 命名与代码风格见 `docs/AI开发约定/代码规范.md`，本项目的结构约定见
  `docs/AI开发约定/项目特定规范.md`。

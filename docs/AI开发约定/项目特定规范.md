# 项目特定规范（mmd2vsdx）

> 只在 mmd2vsdx 仓库成立的约定。通用规范见同目录
> [提交规范.md](提交规范.md)、[代码规范.md](代码规范.md)、[文档规范.md](文档规范.md)。
> 条文里出现"本项目"的地方，都指这个把 mermaid 文本转成原生可编辑 vsdx 的
> 纯 Node/TypeScript 工程。

## 1. 支持范围

- 只支持五类 mermaid 图：**flowchart / block / class / er / sequence**；
- 其余图型不兜底、不降级：归一化层直接抛 `MermaidParseError`，消息里列出支持清单。
  出现"静默变成流程图"这类行为就算缺陷；
- 唯一事实源是 `docs/VSDX解压结构研究/`。实现与验收都对着它的规范版与图型专篇，
  不对着历史产物。

## 2. 仓库结构

```
source/        实现
bin/           可执行入口 mmd2vsdx（命令行），转发到 dist/
tests/         测试，与源码分离
docs/          文档，各区职责见第 7 节
resources/     mmd-input 入库；vsdx-output 本地产出、不入库
temp/          本地开发草稿，不入库，可随时清空
```

`source/` 按流水线分层，依赖只允许自上而下：

| 层 | 目录 | 说明 |
| --- | --- | --- |
| 契约 | `contracts/` | 契约 A（图型 json）与契约 B（部件清单），纯类型，零依赖 |
| 底层 | `common/xml/`、`opc/` | XML 树与序列化、OPC/ZIP 容器，无业务语义 |
| 公用库 | `common/` | 几何、单元格、公式、文本、样式、母版、端口 |
| 解析 | `parser/` | Chromium 加 mermaid 出快照，再归一化成契约 A |
| 图型 | `diag/common`、`diag/class`、`diag/er`、`diag/sequence` | 契约 A 到页面部件，四个包平级、互不 import |
| 打包 | `xml-parts/`、`squeeze/` | 部件组装校验，再压成 OPC/ZIP 字节 |
| 编排 | `convert.ts` | 按 `kind` 分派，管线内的顶层 |
| 适配 | `service/` | 转换、校验、检视、批量四个能力，库 API 与命令行共用 |
| 命令行 | `cli/` | 四个子命令与退出码，只依赖适配层 |

跨组依赖的允许清单：`convert` 可依赖其余全部；`parser` 依赖 `contracts`、`common`；
`diag` 依赖 `contracts`、`common`；`xml-parts` 依赖 `contracts`、`common`、`opc`；
`squeeze` 依赖 `contracts`、`opc`；`opc` 依赖 `common`；`common` 依赖 `contracts`；
`service` 依赖 `contracts`、`common`、`parser`、`xml-parts`、`squeeze` 与 `convert`；
`cli` 只依赖 `service`。新增反向边或跨层边即违规。

脚本分两处：开发期脚本（批量转换、产物校验、架构检查）随 `temp/` 走，不入库；
需要长期留存的辅助脚本只放 `docs/VSDX处理经验/scripts/`。

## 3. 构建与运行

```bash
npm install
npx playwright install chromium   # 首次必做，渲染要 Chromium
npm run build                     # 产出 dist/
npm run typecheck
npm test
```

接入其他工程用适配层或命令行，对外契约见 `docs/接口协议.md`：

```bash
node bin/mmd2vsdx.mjs convert 图.mmd --out 出图.vsdx   # 命令行；- 表示从 stdin 读
```

```ts
import { ServiceSession } from 'mmd2vsdx/service';

const session = new ServiceSession({ outputDir: 'D:/work/vsdx' });
try {
  const r = await session.convert({ text: 'flowchart LR\n  A-->B' });
} finally {
  await session.shutdown();   // 长驻进程退出前必调，关掉 Chromium
}
```

包根还导出四步管线（`Parser`、`renderContract`、`PartsAssembler`、`Squeeze`），
自用可以，跨工程不作稳定承诺：

```ts
import { Parser } from 'mmd2vsdx/dist/parser/index.js';
import { renderContract } from 'mmd2vsdx/dist/convert.js';
import { PartsAssembler } from 'mmd2vsdx/dist/xml-parts/index.js';
import { Squeeze } from 'mmd2vsdx/dist/squeeze/index.js';

const parser = new Parser();
try {
  const a = await parser.convertText('flowchart LR\n  A-->B');  // 契约 A
  const b = renderContract(a);                                  // 契约 B
  const pack = new PartsAssembler().assemble(b.parts);          // 完整包
  const bytes = new Squeeze().pack(pack);                       // .vsdx 字节
} finally {
  await parser.shutdown();
}
```

`dist/` 自包含，运行要 Node 22.2 以上，同目录需有 `node_modules` 里的 playwright
与 mermaid。错误模型：`convertText` 失败抛 `MermaidParseError`；
参数类错误抛 `TypeError` 或 `RangeError`。

## 4. 产物与命名

- 输出名等于输入名：`<stem>.vsdx`。不为了绕开文件锁长期引入 `-fix` 之类新后缀；
- 验收样本名固定，不新增变体：`01-block-1`、`03-class-1`、`04-er-1`、
  `05-flowchart-1`、`06-flowchart-2`、`15-sequence-1` 到 `15-sequence-4`；
- `resources/mmd-input/` 入库；`resources/vsdx-output/` 本地产出、可再生成、不入库；
- 产物字节要确定：zip 的 DOS 时间恒 0，deflate 参数固定，同输入两次转换结果一致。

## 5. 验收口径

- `tests/spec.test.ts` 是主验收：9 个样本逐条断言 `docs/VSDX解压结构研究/` 的准则，缺一即败，
  另有"不支持图型抛错"用例；`tests/master-templates.test.ts` 守母版装配；
  `tests/service.test.ts` 与 `tests/cli.test.ts` 守适配层与命令行的接口契约。
  当前全量 37/37，逐项记录见 `docs/开发过程/02-现状.md`；
- 母版一律程序化：class/er/sequence 用官方模板包内容 verbatim 固化成 TS 模板，
  flowchart/block 用 basic 家族的 5 种节点加 Dynamic connector。
  **官方模具（vssx/vstx）不入库，这是合规红线**；
- 页面严格贴合内容外包围框：页面等于内容盒加两倍半线宽，
  `kCanvasMargin = 0.0053IN`；全图型 `DrawingResizeType=2`，
  避免 Visio 打开时按打印纸倍数放大页面并平移图形；
- 对齐官方模板按五步法走：选包、逐值提取实例代数、最小差异实现、
  Visio COM 实测、审计断言固化。方法见
  `docs/VSDX处理经验/01-官方模板对齐方法.md`。

## 6. 性能基线

> 冒烟口径：仓库内 vitest 计时，浏览器为 Playwright 1.61.1 与 chromium-1228。
> 数字用于看回归趋势，出现两倍以上劣化要查。

| 场景 | 耗时 | 说明 |
| --- | --- | --- |
| 批量转换 9 样本（同进程复用浏览器） | 冷启动 4.7s 加稳态 8 图 0.37s，合计约 5.3s | 串行，顺序等于输入序 |
| 稳态单图（浏览器已预热） | 20 到 110ms 每图 | class/er/sequence 要打包母版，flowchart/block 最轻 |
| convertText 首次（含冷启动与预热） | 约 4.7s | 大头是拉起 Chromium；常驻服务形态按稳态计 |

运行时内存 Node 约 40 到 80MB，未做峰值专项。

## 8. 本项目特有的技术红线

- 单元格 `V` 永远是英寸值，`U='MM'` 只是显示标签，不参与换算；
- 实例代数逐值对官方样本，不发明公式。模板没覆盖的语义显式报不支持或列入
  待核清单，不用自定义结构填坑；
- 母版承载的行为留在母版，不下放到实例；
- 母版里缺失的嵌套子形状必须补齐，少写会让 Visio 自动实例化并撞 ID，
  结果是形状被丢弃；
- 已知坑与结论看 `docs/VSDX处理经验/02-坑位与解法.md`，改渲染器前先扫一遍。

## 9. 本项目的历史整理习惯

零散的工作期提交在定版前按大事件整合，让主干一笔提交对应一个完整事件。
整合属定版前动作，由用户发起，做法见 `docs/VSDX处理经验/03-工具与脚本手册.md` 第 5 节。
平时开发照《提交规范》一篇一提交，不做改写。

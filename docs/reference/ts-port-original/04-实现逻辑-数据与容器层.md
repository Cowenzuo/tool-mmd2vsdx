## 1. core 数据层

### 1.1 类型映射总则

C++ struct 直译为 TS interface；**默认值语义必须保留**（C++ 有默认成员
初始化，TS interface 无运行时默认，需在**构造处**与**消费处**双保险）：

```ts
// C++: struct Node { std::string id; ... double x = 0; NodeShape shape = Rect; }
// TS:
export interface Node {
  id: string;
  label: string;
  shape: NodeShape;        // 必填（构造处给默认）
  x: number; y: number;
  width: number; height: number;
  styleClass: string;
  fillColor: string;
  parentId: string;
  lifelineKind: string;
  dividers: number[];      // 空数组 = 普通节点（C++ 语义：空 vector）
}
export const defaultNode = (): Node => ({ id:'', label:'', shape:'rect', x:0, y:0, width:0, height:0,
  styleClass:'', fillColor:'', parentId:'', lifelineKind:'', dividers:[] });
```

规则：
1. `std::string` → `string`；`double` → `number`；`bool` → `boolean`；
   `std::vector<T>` → `T[]`；`PageId/ShapeId`（uint32）→ `number`（断言整数）。
2. C++ 枚举 → **字符串字面量联合**（便于 JSON 协议直通，免序列化映射）：
   `NodeShape = 'rect'|'roundRect'|'diamond'|'circle'|'ellipse'`。
   注意：枚举名与 JSON 值要分开——C++ 枚举名（Rect）与 JSON 字符串
   （"rect"）目前由 jsonToDiagram 映射，TS 化后 union 直接用 JSON 值。
3. 每个聚合类型配 `defaultX()` 工厂，jsonToDiagram 用 `{...defaultX(), ...raw}` 合并。

## 2. xml 工具层

### 2.1 轻量 XML 树（xmlNode.ts）

```ts
export interface XmlAttr { name: string; value: string; }
export class XmlNode {
  name: string;                 // 本地名（不含前缀），如 'Shape'
  attrs: XmlAttr[];             // 有序（序列化保序，避免依赖对象键序）
  children: XmlNode[];
  text: string;                 // 文本内容（无子节点时有效）
  constructor(name: string);
  setAttr(name: string, value: string): this;
  appendChild(child: XmlNode): this;
}
```

设计要点：
1. **有序属性列表**而非 `Record<string,string>`：VSDX 属性顺序对 Visio
   解析无影响，但保序便于与 C++ 产物 diff（调试期金标准）。
2. **不建模命名空间声明**（ns 前缀一律在 name 里展开，如 `'visio:Document'`）：
   C++ 版用 libxml2 ns 指针管理前缀；TS 版直接在构建时写全名，
   根节点由调用方设置 `xmlns` 与 `xmlns:xxx` 属性（常量表见 2.3）。
3. **序列化器**：
   - 转义：`& < > " '` → `&amp; &lt; &gt; &quot; &apos;`（属性与文本均转义；
     `'` 在属性中用 `&apos;`、文本中可不转但统一转更稳）
   - 自闭合：无子节点且无 text → `<Name a="1"/>`
   - 文本节点原样输出（仅转义）
   - UTF-8：Node 侧全程 string（UTF-16 内部），写出时 `Buffer.from(xml,'utf8')`；
     **注意 BMP 外字符**（emoji）需确认不产生孤立代理项（转义前先 normalize 可选）
4. **解析器**（roundtrip/资源读取用，只读）：手写小解析器（~150 行）
   覆盖：声明跳过、注释跳过、CDATA（作为 text）、实体最小集（amp/lt/gt/quot/apos/
   数字实体）、命名空间前缀保留在 name 中。**不**支持 DTD/外部实体（安全红线）。

## 3. 数字与单元格格式（关键兼容点）

### 3.1 目标

VSDX ShapeSheet 单元格（`<Cell N="PinX" V="3.5" U="in"/>`）的 `V` 是
**数值属性**，Visio 按数值解析。验收标准为"数值等价"（02 §5），
**不追求字节一致**；但尽量贴近 C++ 输出便于 diff 调试。

### 3.2 number 格式化规则（对照 xmlbuilder.cpp:23）

C++：`ostringstream << setprecision(max_digits10=17) << value`
（defaultfloat，即 %g 风格、17 位有效数字）。

TS 实现（两档）：
```ts
// 语义档（默认，产物首选）：JS 最短往返表示 —— Visio 数值完全等价，
// 通常比 C++ 17 位更短更整洁
export const formatNumber = (v: number): string => String(v);

// 对照档（仅调试/对比测试用）：复刻 C++ %g 17 位
// String(v.toPrecision(17)) 后按 %g 规则修剪（去尾零、指数形式阈值 -4/+16）
export const formatNumberStrict = (v: number): string => { /* 见下 */ };
```
`formatNumberStrict` 实现要点（%g 语义）：`toPrecision(17)` →
指数在 [-4, 17) 用定点并去尾零，否则用科学计数（`e+XX` 补零对齐 C++ 输出）；
非有限数抛错（照 C++ `throw invalid_argument`）。

> 测试（TS-804）：对 0、整数、小数、科学计数边界、负零、NaN/Infinity
> 断言两档行为；产物校验器按"数值等价"比较（解析 V 后 |Δ| ≤ 1e-9 相对差）。

### 3.3 appendCell 数值/字符串判定（对照 xmlbuilder.cpp）

C++ 行为：appendCell(parent, name, double, unit?, formula?) 写数值；
appendCell(parent, name, string, unit?) 写字符串（V 属性不转义、原样）。
TS 重载实现为一个函数 + 类型判别：
```ts
appendCell(parent, name, value: number|string, unit?: string, formula?: string)
```
- `typeof value === 'number'` → `V=formatNumber(value)` + 可选 `U=unit`、`F=formula`
- 字符串 → `V=value`（**不做数字转换**，保持 C++ 语义：字符串原样入 V）

## 4. opcpkg 容器层

### 4.1 PartUri（partUri.ts，对照 parturi.cpp）

- 解析：OPC 规则（`/` 开头规范化、禁止 `\`、禁止空段、禁止 `..`、
  扩展名必须非空、大小写不敏感比较用 `toLowerCase`）
- API：`parse(raw): PartUri`、`toString()`、`equals()`、`isDescendantOf()`
- 错误：非法 URI 抛 MmdError（Code 沿用 JsonParseError？——**新增本地
  `OpcError` 或复用 Error**：建议沿用 C++ 的 Error 但扩展 code 枚举不破坏
  兼容；实为 C++ 版 ZipError 独立存在，TS 版统一 `MmdError` + 子类化即可）

### 4.2 ContentTypes（contentTypes.ts）

- 模型：`defaults: Map<extension, contentType>`、`overrides: Map<partName, contentType>`
- 序列化到 `[Content_Types].xml`（根 `Types` + 命名空间常量）；
  查找规则：override 优先，其次 default，都没有→错误
- 特殊：`[Content_Types].xml` 自身与 `.rels` 的处理照抄 package.cpp

### 4.3 Relationships（relationships.ts）

- `Relationship{ id, type, target, targetMode? }`；id 生成规则照抄
  （`rId1` 起递增；注意 C++ 版对删除后的 id 复用策略——按代码照抄）
- 序列化 `.rels`：`<Relationships xmlns=...><Relationship Id Type Target TargetMode?/></Relationships>`

### 4.4 ZIP（zipArchive.ts，对照 ziparchive.cpp 644 行）

**结构**（PKZIP 经典格式）：
- Local File Header：`PK\x03\x04` + version(20) + flags + method + modTime/modDate +
  crc32 + compressedSize + uncompressedSize + nameLen + extraLen
- 数据段（压缩或原文）
- Central Directory：`PK\x01\x02` 每条目 + `PK\x05\x06` EOCD
- 无 ZIP64、无加密、无 data descriptor（C++ 版默认 flags=0，写已知大小）

**与 C++ 逐字段对照清单**：

| 字段 | C++ 值 | TS 实现 |
|---|---|---|
| version needed | 20 | 照抄 |
| flags | `kUtf8Flag=0x0800`（写路径置位） | 照抄；读路径 `kAllowedFlags=0x080e` 校验，`kEncryptionFlags=0x2041` 拒绝 |
| method | `Store=0` / `Deflate=8` | 照抄 |
| modTime/modDate | 固定 DOS 时间（可确定输出） | 照抄（固定 0 或 1980-01-01，与 C++ 对齐） |
| crc32 | zlib crc32 | `node:zlib.crc32`（Node ≥ 20.15 内置）或自研查表 CRC32 |
| deflate | `deflateInit2(-MAX_WBITS, Z_DEFAULT)` = **raw deflate** | `zlib.deflateRawSync(buf, { level: Z_DEFAULT_COMPRESSION })` |
| inflate | raw inflate | `zlib.inflateRawSync` |
| 条目名校验 | `validateEntryName`（长度/非法字符/UTF-8 flag） | 照抄 |
| 路径穿越防御 | `UnsafeEntryName` 拒绝 `..`/绝对路径 | 照抄（安全红线） |
| 限制 | ZipLimits：entries≤4096、archive≤512MB、entry≤256MB、total≤1GB | 照抄常量 + 校验时机 |

**TS 特有注意**：`Buffer` 读写用 `readUInt16LE/readUInt32LE/writeUInt16LE` 等；
大文件用 `Buffer.alloc` 预分配或分块写（Node 流），C++ 是整包内存（512MB
上限内无压力，TS 同策略即可）。

### 4.5 Package（package.ts）

- `OpcPart{ uri, contentType, payload: Uint8Array, compression, dirty }` → TS 同构
- `Package.create()/open(path)`：open 时解包全部部件 + 重建 CT/Rels
- `addPart/removePart/part/contains/partUris`：同构
- `save(path)`：先写 CT 与各 `.rels`（dirty 判定照抄），再整体 zip 写出
- `validate()`：CT 完整性（每个部件有 contentType）、rels 目标存在性

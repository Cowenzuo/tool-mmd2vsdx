### 1.2 收编策略（分两步，风险最低）

**M3 第一步：目录迁入 + 原样运行（零逻辑改动）**
- 整个 mermaid-snapshot 目录移入 `src/snapshot/`（或保留独立目录但纳入
  npm workspace），`.mjs` 原样保留，`snapshot.ts` 用 `createRequire`/
  `readFileSync` 复用——**先打通进程内调用**：
  ```ts
  // renderer.ts（进程内模式）
  export async function renderDiagram(text: string): Promise<SnapshotResult> {
    // 复用现有 snapshot.mjs 的浏览器生命周期（bundle 拼接 + page.evaluate）
  }
  ```
  即：把"HTTP 服务 + 客户端"换成本地函数调用，浏览器页面逻辑一行不改。

**P1 第二步：extract TS 化（可选优化）**
- extract/*.mjs → extract/*.ts，类型标注 `SnapshotResult` 相关字段；
- bundle 拼接机制保留（`build-extract.ts` 生成 IIFE 注入页面），
  或改为 Vite/esbuild 单文件构建（**注意**：页面注入 bundle 不能依赖
  模块系统，IIFE/UMD 形态是硬约束）；
- 若 TS 化收益不明显可**永久保留 .mjs**（TS 生态兼容 JS 导入，
  边界在"类型"而不在"语言"）。

### 1.3 浏览器生命周期（renderer.ts，对照 snapshotclient 职责）

```ts
export class SnapshotRenderer {
  // 单例：浏览器/页面懒加载 + 预热（graph TB; A-->B）
  // 串行队列：同一页面不可并发 evaluate（现状约束保留）
  // 失败恢复：evaluate 抛错 → 重建页面重试一次（现状"崩溃自动重启"语义）
  async render(text: string): Promise<SnapshotResult>;
  async health(): Promise<boolean>;
  async shutdown(): Promise<void>;   // 浏览器关闭，无残留进程
}
```

- 渲染失败降级（gantt 中文语法等）在 extract 内处理（现状行为），
  renderer 只负责通信。
- 与 C++ 版差异：**没有子进程**（浏览器在本进程内），
  `MMD2VSDX_SNAPSHOT_PATH` 等环境变量仅对独立 HTTP 模式（P2）有意义。

### 1.4 独立 HTTP/CLI 模式（P2，兼容层）

- `snapshotService.ts`：`node:http` 服务，`POST /convert`、`GET /health`、
  动态端口（`--port 0`）、ready 行协议——**协议与现状完全兼容**，
  供外部工具独立使用（C++ 版 SnapshotClient 的既有调用方也可继续用）。
- CLI：`node snapshot.mjs "text"` 等价入口。

## 2. mmdtransform

### 2.1 jsonToDiagram（jsonToDiagram.ts，对照 jsonparser.cpp 259 行）

纯函数：`jsonToDiagram(json: unknown): Diagram`。

枚举映射表（**照抄，含默认值**）：

| JSON 字段 | 值 → 枚举 | 默认 |
|---|---|---|
| node.shape | `"rect"→Rect, "roundRect"→RoundRect, "diamond"→Diamond, "circle"→Circle, "ellipse"→Ellipse` | `"rect"` |
| edge.style | `"normal"→Normal, "dotted"→Dotted, "thick"→Thick` | `"normal"` |
| edge.arrowHead | `"none"→None, "arrow"→Arrow, "circle"→Circle, "openarrow"→OpenArrow` | `"arrow"` |
| edge.arrowTail | 同上 | `"none"` |

字段收编（照抄 jsonparser.cpp 的逐字段读取）：
- node：id/label/shape/x/y/width/height/styleClass/fillColor/parentId/
  lifelineKind/dividers（`value(...)` 缺省兜底）
- edge：from/to/label/style/arrowHead/arrowTail/waypoints（数组→Point[]）/
  fromMultiplicity/toMultiplicity
- cluster：id/label/x/y/width/height
- 专用子结构：gantt（tasks/sections/title/dateFormat/startSerial/endSerial）、
  git（commits/branches/arrows）、pie、quadrant、sequence（activations/fragments）
  ——字段名与类型以 extract 实际产出为准（见 04 §1.5 的宽松/收紧原则）
- 顶层：diagramType/direction/bounds（minX/minY/maxX/maxY）/svg
- **未知字段忽略、缺省字段兜底**（与 C++ 的 `value(key, default)` 语义一致）；
  类型不符时兜底或抛 JsonParseError——**与 C++ 行为逐条对照**（这是
  testjson 的核心用例集，275 行测试直接平移）

TS 实现要点：`asRecord(v)` 守卫 + `num(v, fallback)`/`str(v, fallback)`/
`arr(v)` 助手；产出后 `validateDiagram()`（非有限坐标、负尺寸等——对照
CoordinateTransform 构造时的校验，提前在翻译层抛出，错误码 JsonParseError）。

### 2.2 Translator（translator.ts，对照 translator.cpp 46 行）

```ts
export class Translator {
  static shared(): Translator;
  translate(text: string): Diagram;   // 首次调用自动初始化 + 预热
  shutdown(): void;
}
```

- 默认**进程内直调** `SnapshotRenderer.render(text)` → `jsonToDiagram`
- 可选构造参数 `{ mode: 'in-process' | 'http', snapshotPath?: string }`
  （http 模式 = 兼容旧环境变量定位，P2）
- 错误传播：渲染失败 → MermaidError/SubprocessCrashed 语义（进程内模式下
  崩溃 = 渲染器重建失败，错误码保持）；解析失败 → JsonParseError
- **同步 API 的取舍**：C++ 是同步阻塞；TS 建议 `translate` 保持 async
  （渲染本质异步），`Application` 层负责 await；若需同步包装（CLI 顶层）
  用 `await` 即可，无兼容负担（新 API 无历史包袱）

## 3. app 编排层

### 3.1 Application（application.ts）

```ts
export class Application {
  static shared(): Application;
  async convertText(text: string, options?: ConvertOptions): Promise<ConvertResult>; // 新能力：库 API 主入口
  async convertFile(mmdPath: string, outPath: string): Promise<void>;
  async convertDir(inputDir: string, outDir: string): Promise<void>;  // 串行、输入顺序
  serve(port: number): Promise<void>;  // node:http，阻塞（返回 Promise，服务退出时 resolve）
  async shutdown(): Promise<void>;
}
```

- `ConvertOptions`：`{ outputScale?, margins?, useConnectorMaster?, diagramType? }`
  → 映射 CreateOptions（默认值照抄 vsdx.hpp）
- pipeline 编排照抄：`text → Translator → VsdxTranslator → OpcPackager`
- `convertDir`：扫描 `*.mmd`（递归策略照抄 FileScanner）→ 串行 → 同名输出
  （OutPathResolver：完整路径或目录判定照抄）

### 3.2 serve（serve.ts，对照 httpserver.cpp 191 行 + serve.cpp 70 行）

```
POST /convert  {"text": "..."} → 200 {"status":"ok","vsdx": base64, "diagramType", "pageCount"}
                                 或 {"status":"error","message"}
GET  /health → {"status":"ok"}
```

- `node:http` 实现（或 fastify 可选，**默认裸 http 即可**，路由只有两条）
- 串行处理（现状约束保留，TS-907）：内部 Promise 队列
- 请求体上限 1MB（照抄 kMaxBodySize）
- base64：`Buffer.from(vsdxBytes).toString('base64')`
- ConvertHandler 概念保留为内部回调接口（app 注入），便于测试注入 mock

### 3.3 CLI（cli.ts）

```
mmd2vsdx <in.mmd> [out.vsdx]           # 单文件
mmd2vsdx --dir <in> <out>              # 批量
mmd2vsdx --serve [--port N]            # 服务形态
mmd2vsdx --snapshot <path>             # 指定独立 snapshot 脚本（兼容）
mmd2vsdx prepare-stencils --visio <dir> [--out <path>]   # 生成模具资产（M5）
```

- `#!/usr/bin/env node` + `bin` 字段；退出码：成功 0、业务错误 1、用法错误 2
- 输出人性化进度（批量时逐文件打印），错误打印 `[phase] message` + 堆栈

## ① 输入加载（.mmd 读取与输出定位）

### 1.1 输出路径二义性（文件 vs 目录）
- [源码] `app/output.cpp:17`：outPath 是 `.vsdx` 文件时直接写；否则视为
  **目录**，输出 `outDir / (stem + ".vsdx")`。判断"是否文件"要按扩展名/
  现有路径规则，不能想当然。
- TS 要点：路径用 node:path 处理；保持同一判定逻辑（不存在的扩展名路径
  到底算文件还是目录，行为要与 C++ 一致——C++ 是"看起来像 .vsdx 就是文件"）。

### 1.2 批量的顺序保证
- [源码] `app/pipeline.cpp`、README：convertDir **串行**转换、输出顺序 =
  输入顺序（FileScanner 按目录枚举排序）。
- [源码] `app/input.cpp`：**只扫目录顶层 *.mmd（大小写敏感）** +
  字典序——不递归子目录。
- TS 要点：不要为了提速引入并行而破坏顺序；要并行须显式保持输出序
  （先收集后按序写出），否则 e2e 金标准（顺序断言）失败。

### 1.2b 服务形态的半空契约（已知怪癖，移植可修正）
- [源码] `app/serve.cpp`：POST /convert 响应恒 `pageCount=1` 且
  `diagramType` 恒空串——**半空契约**（C++ 版没接线）。
- TS 要点：ConvertResult 字段已备好（core/xmlparts.hpp），TS 化顺手
  填真实值（pageCount=页面数、diagramType=解析类型）；若需与旧客户端
  兼容则保留字段形状只补值。

### 1.3 中文路径（Windows 编码转换）
- [源码] `http/client/snapshotclient.cpp:23,36`：Windows 下 C++ 宽字符路径
  转 UTF-8 **必须 MultiByteToWideChar/WideCharToMultiByte(CP_UTF8)**；
  用迭代器构造 wstring 会破坏非 ASCII（中文路径）。
- TS 要点：Node 天然 UTF-8 无此坑；但注意 **CLI 参数/环境变量在 Windows
  控制台的编码**（PowerShell/GBK 代码页），建议入口显式 `process.argv`
  原样处理，文件读写统一 UTF-8。

## ② 渲染提取（mermaid-snapshot：文本 → SVG + 结构 JSON）

### 2.1 bundle 拼接机制是硬约束
- [源码] `snapshot.mjs:27-49`、`extract/*.mjs` 文件头：Playwright
  `page.addScriptTag` 无法注入带模块依赖的代码，因此启动时把
  extract/*.mjs **按依赖顺序拼接**为单个自包含脚本注入页面：
  文件间**不写 import**、靠拼接后的同一全局作用域（函数声明 hoist）；
  `export` 前缀在拼接时**剥离**。
- [源码] `main.mjs` 注释：跨文件函数引用依赖拼接后的同一全局作用域。
- TS 要点：extract 若 TS 化，**最终注入页面的必须是 IIFE/UMD 单文件**，
  不能依赖 ESM；或保持 .mjs 拼接原样（零风险选项）。

### 2.2 渲染失败降级路径（不能阻断）
- [源码] `main.mjs:21-31`：mermaid 渲染失败（如 gantt 的 after 中文名语法
  不被支持）时**保留空 svg**，仍从文本推断类型并解析 gantt 结构化数据。
- TS 要点：renderDiagram 的"渲染"与"提取"必须解耦；失败仅影响 svg/nodes，
  类型专用数据（gantt 等）照常产出。

### 2.3 图型检测两路径
- [源码] `main.mjs:49-61`：优先 SVG `aria-roledescription`（去掉 `-v2`/
  `-beta` 后缀）；渲染失败/无 SVG 时从**文本首行**推断
  （gantt/sequenceDiagram/classDiagram/stateDiagram/erDiagram/C4/默认
  flowchart）。
- TS 要点：类型名规范化（`classDiagram` vs `class`、`stateDiagram` vs
  `state`）是散落各处的判断依据，TS 化时收敛为单一 `normalizeDiagramType()`
  并加单测（extract 里 flowchart.mjs 有 `isClassLike` 等重复判断）。

### 2.4 direction 推断
- [源码] `main.mjs:33-47`：从 `.node` 的 translate 坐标范围推断
  （xRange>yRange → LR，否则 TB）。
- TS 要点：**依赖节点 transform 解析**；节点数为 0/1 时保持默认 TB。

### 2.5 SVG 命名空间修补
- [源码] `main.mjs:124-128`：C4 图用 `<image xlink:href>`，mermaid 输出
  缺 `xmlns:xlink` 声明 → 手动在 `<svg ` 后注入
  `xmlns:xlink="http://www.w3.org/1999/xlink"`。
- TS 要点：SVG 字符串进 IR（Diagram.svg）再进产物（作为形状背景时），
  命名空间缺失会导致 Visio 侧资源引用失败；此修补必须保留。

### 2.6 flowchart 节点 id 规范化（最易踩）
- [源码] `flowchart.mjs:23-26`：mermaid 给每个节点 id 追加数字索引
  （A → A-0、A-1 → A-1-0）。只剥**尾部** `-\d+$`；用户 id 本身以数字结尾
  （A-1）必须保留。
- [源码] `flowchart.mjs:95-132`：边 path id 形如 `L-<from>-<to>-<index>`，
  **端点 id 可能含连字符** → 先剥尾部数字，再用**已知节点 id 集合做最长
  前缀匹配**消歧。
- TS 要点：这两条是"节点对不上/边 from/to 为空"类 bug 的根源，测试必须
  覆盖 `A-1`、含连字符 id、数字后缀节点。

### 2.7 标签多选择器兜底
- [源码] `flowchart.mjs:34-57`：label 候选依次试
  `.nodeLabel/.label text/.label foreignObject/.classTitle/.classTitleText/
  .label span`，取第一个非空；类图收集**去重后的全部成员文本**按行拼
  （join '\n' → dividers 分割的 VSDX 类框）；class 图还从
  `line.divider` 的 y1 收集分隔线（相对节点中心 y 偏移）。
- TS 要点：类框的成员行顺序 = label 行序，divider 数量与成员分组
  强相关，改动提取 = 破坏类图渲染。

### 2.8 形状识别优先级
- [源码] `dom.mjs:8-15`：detectShape 按内部元素优先级：
  polygon→diamond、circle→circle、ellipse→ellipse、rect 且 rx>0→roundRect、
  否则 rect。
- TS 要点：mermaid 的 `A{text}` 判定必须用 polygon；用 rect 判定会
  全变矩形。

### 2.9 路径采样（parsePathD）
- [源码] `dom.mjs:18-87`：M/L/C/Q 采样（C 8 步、Q 6 步）；**相对命令
  （小写）要叠加上一点**；Z 不产生点；`dom.mjs` 版不支持 A（弧线）。
- [源码] `git.mjs:247-339`：git 专用 parseGitPathD 支持 **A 弧线**（W3C
  椭圆弧参数化 sampleArc，12 步采样，含 large-arc/sweep 象限修正、半径
  放大 lambda 处理）。
- TS 要点：两个解析器用途不同（flowchart 边 vs git 箭头），移植时
  不要合并错；弧线采样公式的象限/方向处理是 pie/git 形状正确性的关键。

### 2.10 边样式与箭头判定
- [源码] `flowchart.mjs:134-143`：style 由 class 判定
  （edge-pattern-dotted/-dashed→dotted、edge-thickness-thick→thick）；
  箭头只看 `marker-end`（空→none、含 circle→circle）——**无法区分
  openarrow 等其余 marker**（openarrow 由 er/class 提取另行处理）。
- TS 要点：这是"箭头类型丢失"的已知边界，不是 bug；移植保持即可。

### 2.11 子图（cluster）提取
- [源码] `flowchart.mjs:153-175`：`.clusters .cluster` 内 rect 的 bbox 中心
  + 尺寸；label 从 `.cluster-label`。
- 已知限制（README）：cluster 目前**不输出到 VSDX**（仅入 IR）。

### 2.12 颜色转换
- [源码] `dom.mjs:109-131`：cssColorToHex 支持 hsl()/rgb()/#hex；hsl 转换
  用标准公式；**失败返回空串**（上层自行兜底）。rgb 分量 clamp+round。
- [源码] `git.mjs:21-31`：分支色从 `<style>` 文本正则
  `\.commit(\d+)\{stroke:...` 提取再 hslToHex。
- TS 要点：颜色解析是"fillColor 为空→默认白"类差异的根源；
  正则提取的容错（引号/空格变体）保留。

### 2.13 gantt 文本解析（SVG 无日期）
- [源码] `gantt.mjs` 全文要点：
  - 日期序列号 `dateSerial = round((UTC(y,m-1,d) - UTC(1899,11,30))/86400000)`
    —— **Excel 序列日**，UTC 起算 1899-12-30；C++ 侧换算
    `(serial-25569)*86400` 转 Unix（gmtime），两侧 UTC 一致。
  - 时长单位：h→/24、w→×7、M→×30、y→×365（默认天）。
  - 依赖解析：`after 任务X` 或"非日期/时长的剩余段"；milestone 判据 =
    `duration===0 && !isAfter && 有日期`——**after 依赖任务不算里程碑**。
  - `endSerial = floor(maxE) + 2`（对齐官方 GC：EndDate=最后结束+2 天，
    否则主刻度比官方少 2 天）。
- TS 要点：TS 侧用 Date.UTC 保持同一起算；**不要**用本地时区 Date 构造
  （会差一天）；`milestone` 判据与 renderer 的判据必须同源。

### 2.14 sequence 提取
- [源码] `sequence.mjs` 要点：
  - actor 检测：`[class*="actor-man"]`（人形 icon）按 **x 中心 ±10px** 匹配
    生命线 → `lifelineKind:'actor'`；participant/隐式 → 'object'。
    嵌套 actor 容器要去重（parentElement.closest 检查）。
  - 消息线：`messageLine0/1` 类名**轮换**，按 y 排序后与 `.messageText`
    按序配对；虚线判定 = attribute + computedStyle 双兜底；
    **x 很近（<20px，子段）时用文本 x ±40 扩展**；全零时回退 actor x；
    端点用 closestNodeByX 匹配。
  - 生命线 y>200 归一化到 50、高度 ≥350（mermaid 复刻 actor bottom 干扰）。
  - 激活条：`rect[class*="activation"]` bbox → 最近 actor（x 距离）。
  - 循环片段：loopLine 集合的包围盒 + loopText/labelText。
- TS 要点：消息线类名轮换 + y 排序配对是"消息错配/丢失"类 bug 根源；
  这些启发式是实测调出来的，移植**一字不改**。

### 2.15 gitGraph 提取
- [源码] `git.mjs` 要点（详见 2.9 弧线采样）：
  - commit 必须**同时查 `circle.commit` 和 `rect.commit`**（HIGHLIGHT 是
    rect）；rect 的 inner 框跳过取 outer；位置取中心。
  - **装饰小圆 r<4 过滤**（cherry-pick 旁 r=2.75 小圆）；同位置去重取大圆，
    merge/highlight/reverse 标志合并。
  - 无 commitN class 的（cherry-pick）按 **y 就近匹配分支线**。
  - commit 标签 `text.commit-label`：标签文本**优先作为 commit id**
    （比 class token 可靠）；tag 标签（tag-label）就近匹配，
    `cherry-pick:` 前缀当 id/label。
  - 箭头 `path.arrow`：端点就近匹配 commit（距离<400）；kind 判定：
    跨分支且 from.y<to.y → branch（向下分出），否则 merge（向上合并）；
    **线色分支：merge=源(子)分支色，seq/创建=目标分支色**。
  - bounds：分支线+commit 后外扩（左 90 右 30 上 30 下 40，标签空间）。
- TS 要点：id 可靠性顺序 = 标签文本 > class token；颜色归属规则错一条，
  整张 git 图线色就乱。

## ③ JSON → IR（jsonparser：容错映射）

### 3.1 status 门禁
- [源码] `jsonparser.cpp:50-53`：顶层必须 `status=="ok"`，否则抛
  Error(MermaidError, message)。TS 化后 snapshot 进程内直调也要保留
  该门禁（渲染失败 ≠ 提取失败）。

### 3.2 枚举映射 + 缺省兜底（错误枚举不能崩）
- [源码] `jsonparser.cpp:11-45,64-93`：映射表：
  - shape: rect/roundRect/diamond/circle/ellipse，未知 → **Rect**
  - style: normal/dotted/thick，未知 → **Normal**
  - arrowHead: none/arrow/circle/**openarrow**，未知 → **None**（注意：
    head 的 JSON 默认是 "arrow"）
  - 字段全部 `value(key, default)` 兜底；unknown 字段忽略。
- TS 要点：**未知枚举值回退默认**而非抛错——这是与"渲染失败"无关的
  容错红线；TS union 类型不能直接 `as`，要写映射函数（用 Record 查表）。

### 3.3 专用子结构按需解析
- [源码] `jsonparser.cpp:129-276`：gantt/git/pie/quadrant/sequence 各自
  `is_object()` 才解析；缺字段/非数组则跳过（不是错误）。
- **isAfter 被有意丢弃**：gantt 提取层在 JS 端预计算 milestone 布尔
  （duration===0 && 有日期 && 非 after），isAfter 字段不落到 IR——
  渲染器按 dependsOn 重算真实日期（见 8.1 的 after 依赖推算）。
- TS 要点：`{...defaultX(), ...raw}` 合并模式实现 value() 兜底语义；
  别"好心"把 isAfter 加回 IR 并改变 milestone 判据（两处会同源漂移）。

### 3.4 契约漂移的静默风险（TS 化最大架构收益点）
- [源码] 提取层"宽松产出" + jsonparser"宽容读/缺省兜底"：
  字段改名/拼写错不会报错，只会**静默降级**（如 shape 未知 → Rect、
  字段缺失 → 默认值）。
- TS 要点：用 04 §1.5 的 SnapshotResult 类型 + 单测锁字段名；
  运行时守卫只验关键字段（id/x/y），不收紧提取层（保持容错）。

### 3.5 IR 与提取字段的"宽松/收紧"契约
- [源码] extract 产出字段与 IR Node 字段高度重合但不完全一致
  （如 sequence 提取的 node 带 lifelineKind，flowchart 的不带）。
- TS 要点：SnapshotNode（提取层输出）与 IR Node（消费层）**分开定义**，
  jsonToDiagram 做字段收编；不要试图让提取层直接产出 IR。

## ④ 翻译与坐标变换

### 4.1 坐标系与缩放（数学硬规则）
- [源码] `coordinatetransform.cpp:35-101`：
  - `scale = outputScale / 96.0`（SVG 像素 96dpi → 页面英寸）；
  - outputScale 必须有限且 >0；margin 必须有限且 ≥0，否则抛错；
  - sourceBounds = diagram.bounds + 全部节点四角 + 边 waypoints +
    cluster 四角；任一坐标非有限 → 抛错；节点宽高 <0 → 抛错；
  - **空内容 → 默认 {0,0,96,96}**（不是 0 尺寸，否则页面崩溃）；
  - `pageWidth = marginLeft + max(contentWidth, 0.1) + marginRight`
    （内容最小 0.1"）；
  - `point(x,y) = { marginLeft + (x-minX)*scale, marginBottom + (maxY-y)*scale }`
    —— **y 翻转**（SVG 向下 → 页面向上）。
- TS 要点：这是全工程最容易"看着对、实际反"的地方；翻转与边距顺序
  必须与 C++ 一致，用 05 文档的正反例测试锁死。

### 4.2 gantt 页面固定尺寸（不走自适应）
- [源码] `diagramimporter.cpp:154` 附近：gantt 页面按 Visio 官方 Gantt
  模板固定 **A3 横向（16.0354"×11.6929"）**，不走 bounds 自适应。
- TS 要点：gantt 分支的页面尺寸是特例，别被通用逻辑吞掉。

### 4.3 翻译三步职责（resolveType/assemble/build）
- [源码] `diagramimporter.hpp/cpp`：resolveType（Auto 推导 + 校验）→
  assembleDocumentCore（建 Package + 文档部件 + 母版打包）→
  buildPageContent（专用渲染器分支或通用 nodes/edges 循环）。
- [源码] `diagramimporter.cpp:121-122`：**package 与 core 各持一个独立
  对象**；C++ 里"不可 move 同一对象两次，否则 core 持有的 Relationships
  悬空崩溃"。TS 无 move，但"容器对象只被一处拥有"的纪律保留
  （DocumentCore 与 Package 的关系别改造成共享可变）。

### 4.4 通用 vs 专用分支判定
- [源码] `diagramimporter.cpp` buildPageContent：gantt/git/pie/quadrant/
  sequence 以 IR 专用数据 `!empty()` 分支（gantt.empty()=tasks 空等）；
  mindmap 走通用节点-边渲染（只是连接线路由不同）。
- TS 要点：分支顺序（先专用后通用）与 empty 判据保持一致。

## ⑤ docmodel（纯数据模型）

### 5.1 页面 = 树的容器（去指针红利）
- [源码] `docmodel/model.hpp:73-92`：PageModel 持有 xml 树根 + shapesNode/
  connectsNode 等**页面级句柄**；ShapeModel/ConnectorModel 纯数据，
  无 XML 指针；shapeNodes/connectorNodes 索引服务于"按 id 刷新"。
- TS 要点：TS 中对象引用即句柄，**shapeNodes 索引机制整体消失**——
  但"模型与树的对应关系"仍要显式维护（shape.nodeRef 或 id→node Map），
  别在重构中把树的组织逻辑弄丢。

### 5.2 反向指针与生命周期
- [源码] `model.hpp:91`：PageModel.document（DocumentCore*）反向指针——
  "母版查询等"用。C++ 用裸指针（无所有权）。
- TS 要点：TS 直接持引用即可；注意别造环导致 GC 问题（无碍，普通引用）。

### 5.3 ID 分配
- [源码] `model.hpp:84`：nextShapeId 从 1 起递增（页内）；PageId 从 0 起。
- TS 要点：ID 空间**按页隔离**（每页自己的 nextShapeId）；母版打包时
  master ID 从 100 起（见⑨）；子形状（MasterShape 骨架）也占页内 ID——
  顺序必须与 C++ 一致（先父后子、渲染顺序），否则产物 ID 分配漂移。

## ⑪ OPC/ZIP 容器（opcpkg）

### 11.1 ZIP 写读细节（对照 ziparchive.cpp 711 行）
- [源码] grep 结果：写路径 deflate 用 `deflateInit2(Z_DEFAULT_COMPRESSION,
  Z_DEFLATED, -MAX_WBITS=raw, 8, Z_DEFAULT_STRATEGY)` → TS =
  `zlib.deflateRawSync(buf, {level: Z_DEFAULT_COMPRESSION})`；
  读路径 inflate 后**必须校验 Z_STREAM_END + 输入吃干**（尾部垃圾/截断
  要报 InvalidArchive）；
- flags：写路径恒置 `kUtf8Flag=0x0800`（UTF-8 文件名）；读路径白名单
  `kAllowedFlags=0x080e`，加密标志 `kEncryptionFlags=0x2041` 拒绝；
- **ZIP64 拒绝**：extra id 0x0001、大小字段 0xffff/0xffffffff 均为
  UnsupportedFeature；
- 条目名校验 validateEntryName：**走 PartUri::parse 规则** +
  UTF-8 校验（未置 0x0800 且含非 ASCII → 拒）；路径穿越防御
  （UnsafeEntryName）；Store 方法 + flags 组合校验（validateFlags：
  Store 不允许 0x0006 位）；
- data descriptor（bit3）：读路径带/不带签名两种形态都支持
  （以 Central Directory 的 CRC/大小为权威）；写路径**不生成**；
- 时间戳：写固定 0（DOS 时间），flags 固定 0x0800——**字节级确定性
  输出**（同一输入永远同一产物，可复现性）；
- CRC32：zlib crc32（**IEEE，含最终 XOR**——历史事故：自研 CRC 从 0
  起无最终异或 → 18 个 VSDX×17 条目全 Bad CRC-32）；
- ZipLimits：entries≤4096、archive≤512MB、entry≤256MB、
  totalUncompressed≤1GB（ziparchive.hpp:36-41）；
  **超限 → 删除已写文件再抛**（不留半成品）；
- **部件保存顺序 = [Content_Types].xml 第一 + PartUri 字典序**
  （package parts 是 std::map；XmlParts 自身顺序不影响产物）——
  TS 用 Map 天然保插入序，要**显式排序**才能复刻字节级顺序。
- TS 要点：raw deflate（无 zlib 头）是**最容易写错**的点（用
  deflateSync 带头会被 Visio/解压器拒或乱码）；产物可复现性依赖
  固定时间戳与排序——这是 e2e/roundtrip 稳定对比的前提。

### 11.2 PartUri / ContentTypes / Relationships
- [源码] parturi.cpp：OPC URI 规范——禁 `\ ? #`、剥前导 `/`、段禁
  空/`.`/`..`/含 `:`、resolve 禁逃出包根、扩展名非空、大小写不敏感

- [源码] relationships.cpp：rId 生成（rId1 起，取最小空闲）；Id 重复

- TS 要点：rels/CT 是 Visio 打开性的第一道门（错一个 Visio 直接拒开）；

## ⑭ TS 化特别提示汇总（跨阶段）

1. **别"统一"特例**：ER 关系线不走普通连接线路径、lifeline 只写
   PinX/PinY、激活条不能写 Angle、gantt 页面固定 A3——每个"看起来
   不合理"的分支都是实测产物。
2. **常量照抄不优化**：17 位布局常量、MM 距离 cap 表、guidFor 哈希、
   硬编码 V 缓存（0.5216535433070867 等）、TxtHeight
   0.2000515258789062——改了产物就漂。
3. **单位语义三件套**：U 是单位标记（MM 的 V 仍英寸）；字符串 cell
   必须 U='STR'；数值 cell 的 U（IN/PT/DEG/DL）按 C++ 每处照抄。
4. **双路径思维**：每个形状/连接线的写法都要问"OLE 快速路径（读缓存）
   与直接打开（重算）两条路径下都正确吗？"——V 与 F 必须自洽。
5. **数字格式化**：V 缓存 16 位精度（masterlibrary os.precision(16)）
   与 XmlBuilder 17 位 max_digits10 是**两套**（克隆重写 vs 新建 cell），
   TS 移植分别实现（04 §3）。
6. **Word 嵌入是隐藏验收项**：纯 .vsdx 打开正常 ≠ 合格；有条件时用
   OLE 嵌入路径复测（13.2 快照断言部分覆盖）。
7. **顺序即协议**：形状 ID 分配顺序、masters.xml 物理顺序、XmlParts
   部件顺序、ZIP 条目顺序——全部影响产物一致性。
8. **文本估宽按 UTF-8 字节循环是全库通用约定**：连接线（renderer.cpp
   :1000-1004：CJK 0.14/3 字节=每字 0.14、ASCII 0.08）、ER（:552-565：
   CJK 0.16/字节、MWmw 0.11、A-Z 0.09、数字 0.065、窄字 0.045…）、
   git（8pt 档 CJK 0.11、MWmw 0.075…）、pie/quadrant（CJK
   fs×0.55/72、pie 另有空格/% 特例）、mindmap 提取（extract：
   CJK 15px/字、ASCII 8px/字）——**TS 按码点移植必须把"中文每字"常量
   折算清楚**（中文常量本来就是按字给、循环按字节算：CJK 权重 =
   字常量/3 × 3 字节；直接按字符循环则用字常量即可），英文按 1 字节。
   估宽只影响文字框预尺寸与排版，数值不需要与 C++ 完全一致，但**同一
   处代码的估算逻辑不能混档**。
9. **V/F/U 三件套铁律**：V 恒为英寸内部值（日期=Excel 序列数），U 只是
   显示单位（U=MM 的 V 也是英寸）；F 是公式（'Inh'=继承上游）、无 F=
   本地覆盖值——两种语义完全不同；V 缓存必须与 F 描述同一状态
   （快速打开不重算直接显示 V，直接打开重算走 F，两路径画面不同 =
   bug）。
10. **软失败与硬失败的分界**：公式求值失败/找不到母版 → 保留原件或
    no-op（软）；输入校验/模型错误 → 抛异常中止（硬）；包 validate
    不过 → 抛（硬）。移植时别把软失败改抛错（会崩在真实样本上），
    也别把硬失败改静默（会产出坏文件）。

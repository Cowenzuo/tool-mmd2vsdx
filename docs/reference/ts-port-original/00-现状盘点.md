## 1. 工程定位与总流程

**mmd2vsdx**：把 Mermaid 文本转换为**原生可编辑的 Visio VSDX** 文档
（不依赖 Visio COM）。设计约束：Mermaid 渲染/布局在 Node.js + Chromium
完成（能力边界冻结、不优化），C++ 引擎负责"翻译 + 容器"。

```
.mmd 文本
   │  (app/input 读文件)
   ▼
┌──────────────────────────────────────────────────────────────┐
│ mermaid-snapshot（Node.js + Playwright/Chromium，独立进程）    │
│   mermaid@10.9.8 渲染 SVG + extract/*.mjs 按图型提取结构       │
│   输出：{svg, nodes, edges, clusters, diagramType, ...} JSON  │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTP POST /convert（127.0.0.1:动态端口）
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ mmdtransform::Translator（单例）                              │
│   SnapshotClient（服务定位/拉起/健康检查/崩溃重启）             │
│   jsonToDiagram（JSON → Diagram IR，纯函数）                  │
└──────────────────────────────┬───────────────────────────────┘
                               ▼ Diagram（core::Diagram）
┌──────────────────────────────────────────────────────────────┐
│ vsdxdoc::VsdxTranslator（单例）                               │
│   DiagramImporter：resolveType → assembleDocumentCore →       │
│                   buildPageContent（通用/专用渲染器）           │
│   serialize：XmlBuilder/XmlPartsBuilder/DocumentParts →        │
│              core::XmlParts（uri + contentType + xml）         │
│   masters：MasterLibrary（嵌入模具解压/选择/打包/样式合并）      │
└──────────────────────────────┬───────────────────────────────┘
                               ▼ XmlParts
┌──────────────────────────────────────────────────────────────┐
│ opcpkg::OpcPackager（单例）                                   │
│   Package（PartUri/ContentTypes/Relationships/ZipArchive）    │
│   → 规范化 + ZIP → .vsdx 文件                                │
└──────────────────────────────────────────────────────────────┘
```

产出 .vsdx 的内部结构（OPC 包）：

```
[Content_Types].xml
_rels/.rels                       → 指向 visio/document.xml + docProps/*
docProps/app.xml / core.xml / custom.xml
visio/document.xml                → 文档根（Windows/Pages 关系）
visio/pages/pages.xml             → 页面清单
visio/pages/pageN.xml             → 每 Diagram 一页（ShapeSheet 形状 + Connect 连接）
visio/masters/masters.xml + masterN.xml  → 官方模具母版实例（按图型打包子集）
visio/windows.xml                 → 窗口布局
```

## 2. 七模块清单（v2 架构）

| 模块 | 命名空间 | 职责 | 门面 | 依赖 |
|---|---|---|---|---|
| core | `mmd2vsdx` | 数据层：IR + vsdx 契约 + XmlParts，纯数据零依赖 | — | 无 |
| xml | `mmd2vsdx::xml` | libxml2 薄封装：XmlDocument/XmlUtils | —（自由类） | libxml2、core |
| opcpkg | `mmd2vsdx::opcpkg` | OPC 容器：Package/PartUri/Relationships/ContentTypes/ZipArchive | `OpcPackager`（单例） | core、xml |
| http | `mmd2vsdx::http` | 通信层：client（HttpClient/SnapshotClient）+ server（HttpServer/ConvertHandler） | — | core |
| mmdtransform | `mmd2vsdx::mmdtransform` | 翻译层：文本→IR 编排 + 契约映射 | `Translator`（单例） | core、http |
| vsdxdoc | `mmd2vsdx::vsdxdoc` | VSDX 文档翻译：translate/docmodel/render/serialize/masters | `VsdxTranslator`（单例） | core、xml、opcpkg |
| app | `mmd2vsdx::app` | 编排：CLI 形态 + serve 服务形态 | `Application`（单例） | 全部 |

依赖方向（只允许向下）：`app → {mmdtransform → http → core}`、
`app → {vsdxdoc → xml → core}`、`app → {opcpkg → xml → core}`。

## 4. 跨模块契约清单（唯一数据通道）

| 契约 | 定义处 | 生产者 | 消费者 | TS 化形态 |
|---|---|---|---|---|
| `Diagram`（IR） | core/ir.hpp | mmdtransform（jsonToDiagram） | vsdxdoc（DiagramImporter） | TS interface + zod 校验 |
| `CreateOptions` | core/vsdx.hpp | app | vsdxdoc | TS interface |
| `XmlParts` | core/xmlparts.hpp | vsdxdoc（XmlPartsBuilder） | opcpkg（OpcPackager） | TS interface |
| `ConvertResult` | core/xmlparts.hpp | app::ConvertHandler | http::server | TS interface |
| snapshot JSON 协议 | 文档约定（mermaid-snapshot/README） | extract/main.mjs | jsonToDiagram | **同一代码库内直接共享类型** |
| HTTP JSON 协议（/convert /health） | 文档约定 | http server | mmdtransform / app | 保留（服务形态）/ 进程内直调 |

> 关键差异点：C++ 时代 snapshot JSON 协议是**跨进程文档约定**；
> TS 化后提取层与转换层同库，协议升级为**编译期类型约束**，这是 TS 生态的最大收益之一。

## 7. 运行形态与部署现状

1. **CLI/库形态**：`Application::convertFile/convertDir`（gen_samples 使用）
2. **服务形态**：`Application::serve(port)` — `POST /convert {text} → {status, vsdx(base64), diagramType, pageCount}`、`GET /health`（默认端口 12138）
3. **mermaid-snapshot 常驻进程**：主程序托管启动（动态端口 + ready 行 + 崩溃重启），亦可独立运行

## 8. 已知限制（冻结边界，TS 化后保持）

- flowchart 子图背景框（clusters）不输出到 VSDX
- gitGraph 连线为 2-D 折线（commit 圆点移动时不重路由）；merge 弧线为折线近似；commit 标签为水平文本（未还原 45° 斜体）
- Mermaid 提取层能力边界冻结：不优化解析/布局质量
- 文档已注明 Linux 移植方案（libcurl + libmicrohttpd）暂不实施 —— **TS 化后此问题自然消失**

## 9. 盘点结论（对 TS 化的启示）

1. **架构可平移**：v2 七模块 + 门面对门面 + 纯数据契约（core）设计本身不绑定 C++，
   平移成本主要在"实现细节"而非"结构"。
2. **重头在 vsdxdoc**：≈7,690 行业务代码（剔 28,009 行生成资源）占业务总量 59%，
   其中 gantt/masterlibrary/renderer 三个文件 ≈ 4,150 行是移植难点集中地。
3. **stencilresources 是数据不是代码**：TS 化后建议改为生成式 `.ts` 资产（gzip base64），
   或改为运行时从 `resources/visio/*.vssx` 读取（需权衡分发合规，见 05）。
4. **协议层收益最大**：snapshot JSON 协议从"文档约定"升级为"编译期类型"，
   http/serve 从"跨进程必要"降级为"可选兼容层"。
5. **测试可直接迁移**：8 套测试的覆盖意图与验收红线全部保留，仅换框架。

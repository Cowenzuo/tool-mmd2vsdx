# 01 · 官方模板对齐方法（五步法）

> 适用：把某图型（class / er / sequence …）从"自创形状 + 合成样式"
> 切换到"官方母版实例化"，并保证 Visio 打开后**不重排、不覆盖**我们的值。
>
> 本文是 class（`364e5aa`）、er（`c255cc9`）、sequence（`9f7b0ce` 起）三轮实战提炼的固定流程。
> 每一步都给出**产出物**与**验收方式**，跳过任何一步都会在后面付出代价。

## 第 0 步：确认基线可用

```bash
npm run typecheck && npm test        # 全绿再动
git status --short                   # 工作区干净
```

产出：可回退的干净起点。改坏了随时 `git checkout -- <file>`。

## 第 1 步：选对官方模板包（选包）

- 官方模板常有两个版本：**旧图型包**（如 `class/`、`ER/`、`sequence/`）与
  **all-in-one 包**（`class-all-in-one/`、`er-all-in-one/`、`seq-all-in-one/`）。
- **一律以 all-in-one 为准**；旧包只作对照（通用件 Rectangle/Dynamic connector 仍从旧包补）。差异实例：

| 包 | class | ER | sequence |
| --- | --- | --- | --- |
| 旧包 | 11 枚（含 Rectangle/Dynamic connector 通用件） | 7 枚（Entity=7…Relationship=11，含通用件） | 11 枚（含通用件） |
| all-in-one | 16 枚（含 7 类关系线型母版，MasterType=541） | 5 枚（Entity=2 / PKAttr=4 / PKSep=5 / Attr=6 / Rel=7） | 12 枚（含 Alt/Operand/Other 片段，无 Note） |
| 合并结果 | 18 枚 | 5 枚 | 14 枚 |

- 判定方法：打开官方页面 `visio/pages/page1.xml`，看实例 `Master="N"` 指向的
  母版在 `masters.xml` 里的 `NameU`，与两个包的条目集合对照。

产出：`source/common/masters/templates/<type>.ts`（条目 = `{masterType, contentXml}`，
内容 **verbatim** 官方 `MasterContents`）。
生成器：`docs/VSDX处理经验/scripts/gen-type-templates.mjs`（多包合并，通用）。

验收：`tests/master-templates.test.ts` 断言"条目集合与官方包一致 + 内容逐字节等价 + MasterType 保真"。

## 第 2 步：提取官方实例代数（逐值）

对官方页面里的**每一个实例**做 cell 级解剖，产出"实例代数"：

1. **根 Cells**：哪些写、哪些不写（最小差异原则）。
2. **段结构**：`User / Control / Connection / Geometry / Character` 的顺序与
   `IX='0'` 覆写（见坑位与解法 2.1）。
3. **关系线**：W/H 公式、Pin/LocPin、Connection 吸着位、User 行族、
   子形状（MasterShape）旋转与 LocPin。
4. **容器**：高度公式、行堆叠步进、成员行的子形状结构。
5. **文本**：`<Text>` 落在哪个形状上、TxtPin 位置公式。

工具：深度感知解析脚本（当年为 `temp/er-*.mjs` / `temp/_*.mjs` 系列，随
`temp/` 清理不在盘上；片段见 [03-工具与脚本手册.md](03-工具与脚本手册.md) 第 2 节，可原样重建）。
**不要用非贪婪正则抓成员列表**——曾两次静默截断（坑位与解法 4.1）。

产出：注释里的"官方逐值"清单（直接写在渲染器源码顶部，如
`source/diag/er.ts` 的关系实例代数注释块）。

## 第 3 步：实现（最小差异实例化）

- 渲染器只写**与母版不同的差异 cell**；行为组（几何/箭头/连接点）留给母版。
- 每个数值都注明来源（"官方 #15 值"、"官方 #21 逐值"），便于回归比对。
- 关系线/容器这类复合结构，先写"代数推导"再写代码，避免拍脑袋常数。

产出：`source/diag/<type>.ts`、`source/parser/ext/<type>.mjs`（布局/边提取）、
`source/contracts/a.ts`（布局字段）、`source/parser/normalize/generic.ts`（归一化）、
`source/common/styles/writer.ts`（官方文档基座）。

## 第 4 步：Visio 实测（渲染真值）

**这是最重要、也最容易被跳过的一步**。结构审计通过 ≠ Visio 打开正确。

```powershell
# 复制到 temp 再打开（避免锁住产物）
Copy-Item resources/vsdx-output/<样本>.vsdx temp/er-render-src.vsdx -Force
powershell -NoProfile -ExecutionPolicy Bypass -File docs/VSDX处理经验/scripts/visio-probe.ps1 temp/er-render-src.vsdx
# 探针脚本在库内（docs/VSDX处理经验/scripts/），说明见 03-工具与脚本手册.md 第 1 节
```

读 `CellsU('Height').ResultIU` / `PinY` 等，判断：
- Visio 是否**保留**我们写入的值（一致 → 正确）；
- 是否**重排/覆盖**（不一致 → 我们写错了，或触发了容器行为）。

实战收获：ER 的"2 属性实体行组上移"最终就是靠这一步定位的——
Visio 值与我们写入一致，说明不是 Visio 重排，而是**我们自己布局取错了盒顶**
（坑位与解法 4.3）。

## 第 5 步：审计断言固化

把第 2 步的代数写成 `tests/spec.test.ts` 的断言，**表达官方语义**而不是"能过就行"：

- 高度公式：`H = HdrHgt + n×rowH`（不是"高度存在"）；
- 行堆叠步进：属性→属性=rowH、属性→分隔线=rowH/2；
- 关系线：`W=GUARD(EndX-BeginX)`、L 形几何、端标记 6..9、端口 `ToPart=100+IX`；
- 段覆写：`<Section N="Geometry" IX="0">`。

同时更新 `tests/master-templates.test.ts` 的官方包引用。

产出：可长期回归的断言；以后改布局公式会被立刻打回。

# 02 — 系列需求规格（TS 化）

> 本文是 TS 端实现的需求契约。规格按"总需求 → 分层功能需求 → 非功能需求 →
> 优先级 → 验收标准"组织，每条需求带编号（TS-xx），实现逻辑文档（03–06）
> 逐条对应落地。
> 状态：设计期，供评审。

---

## 1. 总体需求

### TS-01 产品定位
把 mmd2vsdx v2（C++17 + Node 双栈）平移为**单一 TypeScript 生态实现**：
一个 npm 包，同时提供库 API（convertText/convertFile/convertDir/serve）、
CLI（mmd2vsdx 命令）与 HTTP 服务形态，行为与 C++ 版功能等价。

### TS-02 兼容边界（必须保持的能力）
| # | 能力 | 说明 |
|---|---|---|
| 1 | 14 类 Mermaid 图 | flowchart/state/class/er/sequence/block/gantt/pie/gitGraph/mindmap/timeline/quadrantChart/xychart/c4 |
| 2 | 原生可编辑 VSDX | 官方模具母版实例（Master="N" + 实例局部覆盖）、1-D 连接线 + `_WALKGLUE` 粘附、五种节点几何、线型/箭头映射、多页 |
| 3 | 按 DiagramType 打包母版子集 | basic/flowchart/class/sequence/er/gantt/timeline/calendar/git |
| 4 | 已知限制保持冻结 | clusters 不输出、gitGraph 折线近似、提取层不优化（见 00 §8） |

### TS-03 交付形态
- npm 包 `mmd2vsdx`（暂名）：ESM + 类型声明，Node ≥ 22
- 三形态：库 API / CLI / HTTP serve
- monorepo（pnpm workspaces）或单包多目录，**推荐单包 + src 分层**（规模小，单包更简）

## 2. 分层功能需求

### 2.1 core 数据层（TS-100 组）

| # | 需求 | 验收 |
|---|---|---|
| TS-101 | 定义 IR 类型（Node/Edge/Cluster/Diagram + 全部专用语义），字段与枚举语义与 core/ir.hpp 完全一致 | 类型可编译；默认值一致（x=0/width=0/…） |
| TS-102 | 定义 vsdx 契约（ShapeStyle/CreateOptions/PageSpec/ShapeSpec/ConnectorSpec + PageId/ShapeId） | 与 core/vsdx.hpp 一致 |
| TS-103 | 定义 XmlPart/XmlParts/ConvertResult | 与 core/xmlparts.hpp 一致 |
| TS-104 | 统一错误类型（错误码：NodeNotFound/JsonParseError/SubprocessCrashed/MermaidError + 消息） | 所有模块抛同一错误类型 |
| TS-105 | snapshot JSON 协议的编译期类型（`SnapshotResult`）：svg/nodes/edges/clusters/diagramType/direction/gantt/git/pie/quadrant/sequence/boundingBox | 提取层返回类型与 jsonToDiagram 入参类型为同一 interface |
| TS-106 | 运行时校验（可选 zod 或手写守卫）：对 snapshot JSON 做轻量字段校验，失败报 JsonParseError | 畸形 JSON 不崩溃、错误信息可定位 |

### 2.2 提取层（mermaid-snapshot 收编，TS-200 组）

| # | 需求 | 验收 |
|---|---|---|
| TS-201 | 保留 mermaid@10.9.8 渲染 + Playwright Chromium 离屏渲染管线 | 与现状同版本、同行为 |
| TS-202 | extract/*.mjs 收编为 TS（浏览器内 bundle 拼接机制保留或改为单文件 IIFE 构建） | 行为等价；bundle 构建纳入 npm script |
| TS-203 | 渲染失败降级路径保留（如 gantt 中文语法失败时仍解析文本） | 与 main.mjs 现行为一致 |
| TS-204 | 提供进程内 `renderDiagram(text): Promise<SnapshotResult>` API（替代 HTTP 协议） | 提取层可直接被 mmdtransform 调用 |
| TS-205 | 保留 HTTP 服务模式（--http）与 CLI 模式（兼容独立使用场景） | 协议兼容现状（/convert、/health、动态端口、ready 行） |
| TS-206 | 浏览器/页面生命周期管理：单例复用、串行队列、预热、失败重启 | 与 snapshotclient 现状等价 |

## 3. 非功能需求

| # | 需求 | 指标 |
|---|---|---|
| TS-901 | 单图端到端耗时（服务形态，预热后） | ≤ C++ 版 × 1.2（预期持平） |
| TS-902 | 批量 16 样本全量 | 全部成功，顺序 = 输入顺序 |
| TS-903 | 产物打开性 | 生成的 .vsdx 可被 Visio / 解压工具打开；roundtrip 通过 |
| TS-904 | 依赖体积 | 运行时仅 mermaid/playwright；无 CDN；可离线 |
| TS-905 | 错误可诊断 | 错误带上下文（图类型/阶段/消息），CLI 打印可读堆栈 |
| TS-906 | 内存 | 批量转换逐文件写出，不累计持有结果 |
| TS-907 | 并发安全 | 服务形态请求串行（或显式队列），行为确定 |
| TS-908 | 分发合规 | npm 包不含官方模具；`prepare-stencils` 由用户本机提取（保持现状红线） |

## 4. 优先级

| 优先级 | 范围 |
|---|---|
| **P0（核心闭环）** | TS-100~106（core）、TS-401~404（xml）、TS-501~506（opcpkg）、TS-601~605、607（vsdxdoc 主体）、TS-301/302（mmdtransform 进程内）、TS-701/702（app）、TS-801~804（测试） |
| **P1（完整能力）** | TS-606（专用渲染器）、TS-608/609（masters + 资源）、TS-610（多页）、TS-703（CLI）、TS-204~206（提取层收编）、TS-303/304 |
| **P2（兼容与增强）** | TS-205（HTTP 独立模式）、TS-202（extract TS 化——可先保留 .mjs 原样）、TS-106（zod 校验）、批量并行（可选增强） |

> 建议顺序：P0 先建立"文本→IR→XmlParts→.vsdx"最小闭环（用 fixture JSON
> 绕过渲染），再接 P1 真实渲染与专用图型，最后 P2 兼容层。
> 详细阶段划分见 03 §6 里程碑。

## 5. 验收金标准（贯穿全部阶段）

1. **语义等价**：16 样本产物与 C++ 版产物"结构等价"——部件清单一致、
   每个部件可被 XML 解析、关键 ShapeSheet 单元格数值一致（浮点允许
   ≤1e-9 相对差，格式化文本允许不同但数值等价）。
2. **打开性**：产物通过 roundtrip（TS 自读）与结构校验器。
3. **测试全绿**：对应阶段 vitest 全绿；每阶段完成 = 构建 + 测试通过。
4. **性能不倒退**：服务形态单图耗时 ≤ C++ 版 × 1.2。

母版内部比对（按 BaseID 匹配，逐母版统计 User 行数/公式、子形状结构）：
- 各母版 **User 行集合与公式完全一致**（如 M=100 母版 31 行、M=113/111 母版 19 行、M=115/110 母版 15 行，均无"仅参考有/仅当前有"差异）

**结论：当前文件打包的母版 = 官方母版的等价副本（重新编号），母版层完整。**

```
ID=1    M=100 Frame         框架: User 18行(Scalar/ScaleStart/ScaleEnd/HeaderHeight/
                             LastColGUID/LastRowGUID/IDColumnGUID...), Width/Height 公式驱动
ID=19,11 M=114 NonWork×2    非工作时间高亮条: PinY=GUARD(Sheet.7!PinY-Sheet.7!User.HeaderHeight)

ID=35..160 M=115 TextEntry×44  文本输入(每行4个=任务名/开始/完成/工期):
                            PinX=Sheet.列!PinX, PinY=Sheet.行!PinY,
```

**整体逻辑**：85 个形状**全部平铺在页面根层**（无父子嵌套于页面，任务条/里程碑的 8 子形状在其自身 `<Shapes>` 容器内）。组件间通过：
1. **Sheet 公式引用**（PinY 链、PinX 链、Width/Height 引用行/列/框架）
2. **GUID 关联**（User.GCChartGUID 全图同 1 个、GCRowGUID/GCColGUID 指向所属行/列、GCVisioGUID=形状 UniqueID）
3. **Prop 引用**（Text Entry 的 User.Field=任务条!Prop.Xxx）
4. **Connection 锚点**（连接线两端挂在任务条的 Connections.LeftSide/RightSide）

### 1.4 ID 分配模式

- 参考 ID **非连续、有空洞**：1~94 连续（含子形状），随后 101~160 段出现空洞（95~100,111,116,122,136,151,156 等缺失），最后连接线 ID=391。推测：Visio 编辑期删除/重插形状不复用 ID，且 391 是后期追加（对应被删除的一批 ID）。
- 参考**每个顶层形状都有 UniqueID**（85/85），且 `User.GCVisioGUID` = 该 UniqueID（GUID 全局唯一）。

### 2.2 结构差异（逐项）

1. **母版编号重排**（113→111、114→109、115→110）。BaseID 与参考一致，页面内自洽可渲染；但若两文件母版混入同一文档/模具会冲突。

2. **框架 M=100 实例**：参考 `Width F=Sheet.7!PinX+Sheet.7!Width-Sheet.2!PinX`、`Height F=Sheet.25!PinY+HeaderHeight-Sheet.81!PinY+Sheet.81!Height`（公式驱动，随列/行自适应）；当前**全静态数值**（无 F）。参考实例 User 18 行（含 LastColGUID/LastRowGUID/IDColumnGUID/WDLookup/WHLookup/WTScalar）；当前 13 行（缺上述 6 行，多 HeaderHeight）。→ 手动调列宽/行数时当前框架不跟随。

3. **行 M=102 实例**：参考 User 5 行含 `GCPrevRowGUID`；当前 4 行**缺 GCPrevRowGUID**。

4. **任务条 M=103 实例**：
   - 子形状：**结构与顺序完全一致**（MS=10,5,9,6,7,11,12,13，每任务条 8 个）。参考实例子形状显式写 `F="Inh"` 值（PinX/Geometry/User.TextLeft 等）；当前实例子形状**全空**（`<Shape ID MasterShape />`）。功能上等价（继承母版），但信息量少。
   - 参考 User 19 行含 `ParentModelGUID`；当前 20 行**缺 ParentModelGUID**（多 IsSummary 等）。
   - Property：参考 8 行（Name/Start/End/Duration/**ActualStart/ActualEnd/UserDefTime**/TaskID）；当前 5 行（Name/Start/End/Duration/TaskID），**缺 3 个实际时间属性**。
   - 参考实例带 `NameU="Task bar" Name="任务栏" Type="Group" Comment` 等元数据；当前无。
   - 参考实例有 Connection 段（LeftSide/RightSide）；当前实例无（但母版有，功能等价）。

5. **刻度**：
   - 当前**只有主刻度 M=111 ×19**，**缺次刻度 M=112 ×1、非工作时间 M=114 ×2**。
   - 当前主刻度**用 `<Text>` 字面文本**（'1/1','2',...,'19'），**无 Field 段**；参考用 **Field 公式** `User.PreText&FORMAT(User.StartDate,INDEX(Sheet.1!User.PriScaleUnitsType,Sheet.1!User.PriScaleCellTextFormat))` → 刻度文字随日期自动更新，当前为静态文本。
   - 当前 Width `F=User.ScaledDuration`（无缩减）；参考 `F=User.ScaledDuration-(User.LeftWidthReduction+User.RightWidthReduction)`（首尾单元格在缩放时缩减贴边）。当前 User 行缺 TextWidth/LeftWidthReduction/RightWidthReduction/PreText。
   - 参考主刻度 PinY 有 `LocPinY`、Paragraph 对齐等；当前简化为 0。

6. **文本输入 M=110（=参考 M=115）**：
   - 当前 Field.Value = **字面文本**（'需求分析' 等，无 F）；参考 Field.Value `F="Inh"` 继承母版 `FORMATEX(User.Field,...)`，User.Field=`Sheet.任务条!Prop.Xxx` → **官方为公式驱动（数据源在任务条 Prop），当前为一次性静态文本**。
   - 当前实例缺 Character/Geometry/Paragraph/Actions 段（母版有，功能等价）。

7. **UniqueID**：参考 85/85 顶层形状有 UniqueID 且 `User.GCVisioGUID` 同步；当前 **0/51**。影响：GUID 关联模型（GCChartGUID/GCRowGUID/GCColGUID 是"同一个逻辑行/列"的身份证，跨文件数据交换时靠它）。

8. **ID 分配**：当前 1~83 **连续无空洞**（生成器顺序分配，合理）；参考非连续含空洞（Visio 编辑特征）。此项非缺陷。

9. **缺失类型**：里程碑 M=104、连接线 M=105、次刻度 M=112、非工作时间 M=114 **完全未实例化**（母版已打包但页面没用）。

10. **多余形状**：M=106 '项目计划' 标题 ×1（参考页面无此形状）。

## 三、根因与修复方向（建议，不改代码）

### 根因推断

1. **渲染器只实现了官方 13 母版中的 8 类的实例化**：Frame/Column/Row/TaskBar/TextEntry/主刻度/标题，未实现 SecScale(112)、NonWork(114)、Milestone(104)、LinkLine(105) 的页面实例。母版层靠打包官方母版补齐，页面层是"够用即止"。
2. **刻度/文本用字面 `<Text>` 而非 Field 公式**：因为公式驱动需要任务条 Prop 与 FORMATEX 链路，静态文本实现简单；代价是失去联动。
3. **UniqueID 未生成**：GUID 关联体系（GCChartGUID/GCRowGUID/GCColGUID 虽已写入，但 GCVisioGUID 应与 UniqueID 一致）未闭合。
4. **框架静态化**：为省公式链，框架 Width/Height 写死；行/任务条/文本的 PinX/PinY 公式链本身已实现（与参考一致）。

### 修复方向（按优先级）

1. **补齐页面实例**（复用已有母版，参考的 Offset/Duration 数据即可）：
   - 次刻度 M=112 ×1（PinY=Sheet.7!PinY，Field 公式）
   - 非工作时间 M=114（周末：从 StartDate 起按日判断，2 段示例）
   - 里程碑 M=104（Duration=0 的任务行，Width=0，8 子形状）
   - 连接线 M=105（有依赖的任务对：BeginX/EndX 锚到两任务条 Connections.LeftSide/RightSide）
2. **刻度改 Field 公式**：主/次刻度 Field.Value=`User.PreText&FORMAT(...)`，补 TextWidth/LeftWidthReduction/RightWidthReduction/PreText，Width 公式还原缩减项；文本输入改 `F="Inh"` + User.Field 公式（数据源收敛到任务条 Prop）。
3. **UniqueID**：为全部顶层形状生成 GUID，并同步 `User.GCVisioGUID`；GCRowGUID/GCColGUID/GCChartGUID 保持与参考一致的全局关联（同一逻辑行/列的 GUID 一致）。
4. **框架公式化**：Width/Height 改为引用列/行（如参考公式），补 LastColGUID/LastRowGUID/IDColumnGUID；行实例补 GCPrevRowGUID；任务条补 ParentModelGUID 与 ActualStart/ActualEnd/UserDefTime。
5. **元数据**：实例补 NameU/Name/Type/Comment（如 `NameU="Task bar" Name="任务栏"`）。
6. **去重**：移除页面上的 M=106 标题形状（参考页面无标题；若产品需要标题，应作为可选项而非默认）。

### 附：验证建议

- 修复后逐项复核：形状总数应=参考（含 112/114/104/105 实例）；刻度/文本 Field 公式存在且无字面文本；85 顶层形状全部带 UniqueID；框架 Width/Height 为公式；用 `show_tree.py`（已支持 `<Shapes>` 容器）复查树。

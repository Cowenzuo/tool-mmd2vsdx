## 一、转换流水线（一次 convertText 的旅程）

```
Mermaid 文本
   │  ① snapshot 渲染
   ▼
SnapshotRenderer.renderDiagram(text)
   ├─ 惰性启动 chromium；页面注入：
   │    extract bundle（14×.mjs 剥 export 按依赖序拼接 → window.__mermaidSnapshot）
   │    + mermaid UMD（node_modules/mermaid/dist/mermaid.min.js）
   ├─ initialize({startOnLoad:false, securityLevel:'loose'}) + 预热 graph TB; A-->B
   └─ 串行队列执行 evaluate；失败重建页面一次
   ▼
SnapshotResult（core/snapshotTypes.ts，浏览器返回的图结构 JSON）
   │  ② IR 收编
   ▼
jsonToDiagram(json)  —— 纯函数：类型分派 8 图类 + 字段兜底 + 空判定
   ▼
Diagram（core/types.ts）
   │  ③ 类型解析
   ▼
diagramImporter.resolveType —— Auto 推导 outputScale / 母版选择；装配 CreateOptions
   │  ④ 导入装配
   ▼
diagramImporter.translate
   ├─ validateStyle/validateShapeBounds（docmodel/validator，渲染前失败即中止）
   ├─ assembleDocumentCore：Package + document/pages 部件 + Relationships + DocumentCore
   │     （装配期注入 masterClient：masterless 或 realMasterClient）
   ├─ buildPageContent：coordinateTransform（render/ 子包，源 px → 英寸，页边距/尺寸校验）
   │     → PageModel → 工厂 dispatch：
   │         gantt → renderGantt          sequence → renderSequence
   │         pie   → renderPie            git    → renderGitGraph
   │         quadrant → renderQuadrant    其它   → renderManaged* 通用渲染
   │     → 连接线粘附（connectorBinder：端口选择/箭头/Connect 行）
   └─ 每页一次 refreshConnectors（把 shapes 的 Connections.X1.. 粘到目标）
   ▼
DocumentCore（docmodel：模型对象持有 live XmlNode 引用 + 脏标记）
   │  ⑤ 序列化
   ▼
xmlPartsBuilder.build
   ├─ 无页面抛错 / needsRecalculation → custom.xml RecalcDocument=true
   ├─ 脏部件 flush（document/pages/dirtyPages → documentParts 工厂重建根）
   ├─ 页关系同步（pagesRelsDirty）
   └─ package.validate()（CT 一致性/关系完整）→ 全部部件 payload
   ▼

   │  ⑥ 落盘（两种出口）
   ├─ application.convertText → ConvertResult（vsdxBase64 内存态，给 HTTP/serve）
   └─ application.convertFile → OpcPackager/Package.save 写 .vsdx 文件
```

## 二、进程生命周期（snapshot/application）

- **惰性单例**：首次 `convert*` 才 launch chromium；`translator` 与
  `SnapshotRenderer` 生命周期由 `application.shutdown()` 统一收口
  （幂等：关页面 → 关浏览器）。
- **串行队列**：同一页面不可并发 evaluate；renderDiagram 内部 promise 链保证
  全局串行；批量/HTTP 并发请求共享同一队列（正确性前提）。
- **失败自愈**：evaluate 抛错 → 重建页面重试一次；预热失败不致命。
- **shutdown 语义**：`cli --serve` 退出 / 批量收尾 / 测试 teardown 都会显式调用；
  进程因此能干净退出（Chromium 句柄不悬挂）。

## 三、快照注入与构建资产（运行期装配）

```

   │   —— vitest 直跑 src（src/snapshot/extract）……
```

## 四、母版资产管线（供应与生成，官方模具不随包）

```

   │ scripts/gen-stencils.mjs（自含轻量 zip 读 → styles/masters/rels 提取）
   ▼
assets/stencils/stencil-data.json（646KB 开发资产；测试/CI/私自分发形态 B）

── 运行期供应（stencilAssets.ts：asset 文件 > 模具目录 > 本机搜寻+缓存） ─
目标机首次真实母版转换 ensureStencilAssets：
   1) --stencil-asset <file>   预生成资产文件（可私下分发，无 Visio 可用）
   2) --stencil-dir <dir>      官方模具目录（现场提取；内容指纹识别 8 类，
                               无关模具忽略；缺类报错引导）
   3) 缺省                     自动搜寻本机 Visio Content 目录（Windows
                               常见布局）→ 提取 → 缓存 %LOCALAPPDATA%/
                               mmd2vsdx/stencil-data.json（指纹失效）
   4) --no-stencil-search      关闭搜寻
   未就绪：masterLibrary 读取抛 [assets] 引导错误（ok=false / exit 1）
   ▼

   ├─ pack：母版 ID 从 100 起重写（gantt 母版洞 109-111 → +3 平移）
   ├─ masters.xml 按 wanted 顺序重排、保留 relIds
   ├─ 跨 stencil 复制连接器母版时补 xmlns/xmlns:r
   ├─ connector/lifeline 母版规范化（去多余 Control 手柄等）

   └─ applyInstanceOverrides：实例级公式求值（MIN/MAX/IF/AND/OR/BOUND、

   ▼
realMasterClient()（MasterClient 实现：masterIdFor/masterShapeId/childShapes…）
```

## 五、批量与 HTTP 驱动

- **convertDir**：`listMmdFiles` 排序遍历、串行转换、首错即止（编排语义简洁）。
- **scripts/batch-convert.mjs**（逐文件容错版）：import `dist/app/application.js`，
  单文件 try/catch 不中断，进度每 25 打印，`_report.json` 记 total/ok/failed/
  totalMs/results，收尾显式 shutdown——256 文件真实转换 0 失败 / 28s。
- **serve**：`POST /convert`（body=文本）→ ConvertResult JSON（base64 字段），
  `GET /health`；单 worker、共享渲染队列。

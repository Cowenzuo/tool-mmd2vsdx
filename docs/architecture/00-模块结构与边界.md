# 00 模块结构与边界

> 本文件数据由依赖提取脚本对全部 `.ts` 的 `import` 语句实测生成（134 条文件级边），
> 非人工默写；分层图见 `diagrams/arch-overview.mmd`。

## 一、分层总览（自底向上）

```
L0 基础层   core（纯类型/常量/错误）     xml（自研 XML 栈 + VSDX 常量）
L1 容器层   opcpkg（OPC/ZIP 包容器）      ← 只依赖 L0
L2 快照层   snapshot（进程内 Mermaid 渲染器） ← 只依赖 L0
L3 业务层   mmdtransform（快照→IR）      vsdxdoc（IR→VSDX 文档模型→XML 部件）
            └ 两者只依赖 L0/L1/L2，彼此不互相依赖
L4 编排层   app/application（四种驱动）  ← 依赖 L3+L1
L5 入口     cli.ts                        ← 只依赖 L4
```

### 实测模块依赖边（目录级，去重）

```
cli.ts      -> app
app         -> core, mmdtransform, opcpkg, vsdxdoc
mmdtransform-> core, snapshot
snapshot    -> core
vsdxdoc     -> core, opcpkg, xml
opcpkg      -> core, xml
xml         -> (无)        core -> (无)
```

要点：
1. **无反向/跨层边**：vsdxdoc 与 mmdtransform 平级、互不依赖（对话通过 `Diagram` IR
   与 `SnapshotResult` 完成，接口即 core 中的纯类型）；
2. **app 是唯一扇出面**：编排层同时触达四个下层，但都是门面 API；
3. **分层内部** 134 条文件级边全部符合目录归属（无越层文件 import）。

## 二、模块卡

### L0 core —— 零依赖纯类型层（5 文件）
| 文件 | 内容 |
| --- | --- |

| `vsdx.ts` | 公共 CreateOptions/ShapeStyle/Page/Shape/Connector Spec + waypoints 工具 |
| `xmlparts.ts` | 跨模块流转契约 `XmlPart(uri/contentType/xml)` + `XmlParts` + `ConvertResult`（纯数据，vsdxdoc 输出、opcpkg 打包输入的唯一边界） |
| `errors.ts` | `MmdError`(4 码) + `isMmdError` |

### L0 xml —— 自研 XML 栈（3 文件，字节对齐 libxml 输出形状）
| 文件 | 内容 |
| --- | --- |
| `xmlNode.ts` | 轻量树（有序 XmlAttr[]、混合内容）+ `parseDocument`（无 DTD 手写解析）+ `serializeDocument` + 全套树 API |
| `xmlBuilder.ts` | VSDX ShapeSheet 便捷写手：`number()/cppFixed6()/setNumericCell/appendCell* /appendSection/appendRow/replaceShapeText…` |

> 边界规则：**上层只允许经 xmlNode/xmlBuilder 建树**；跨层传树用 live 对象引用，

### L2 snapshot —— 进程内渲染器（1 文件 + 14 注入脚本）

### L3b vsdxdoc —— VSDX 文档层（18 文件，子包 6 个）
```
vsdxTranslator.ts          门面 translate(Diagram, options?) → XmlParts
├─ translate/  diagramImporter（Diagram→DocumentCore 三步：resolveType/assemble/buildPage）
├─ docmodel/   model（纯数据 PageModel/ShapeModel/ConnectorModel）+ documentCore（装配态：脏标记/命名/URI 分配）
│              validator（模型/参数校验：颜色/样式/形状边界——translate 与 render 共用，归位消除反向依赖）
├─ render/     renderer（通用渲染+工厂派发+pageShapes 容器守卫+renderManaged*）
│              coordinateTransform（px→inch 页面坐标，importer 与专用渲染器共用）
│              connectorBinder（端口/箭头/粘附） · pi/quadrant/git/sequence/gantt（图类专用渲染器）
├─ masters/    masterClient（MasterClient 抽象 + masterlessClient + 母版名解析）
│              masterLibrary（装载/pack ID 重写/mergeStyles/applyInstanceOverrides）
│              stencilAssets（资产运行时供应：asset 文件/模具目录/本机搜寻+缓存；
│              资产数据 assets/stencils/stencil-data.json 为开发资产、不随包）
└─ serialize/  documentParts（各部件 XML 根构造）
               xmlPartsBuilder（DocumentCore→XmlParts：脏部件 flush → package.validate）
```

> 文件归位说明（结构整理动作，2026-09）：`coordinateTransform` 由 translate 子包移至
> render 子包、`validator` 由 serialize 子包移至 docmodel 子包——原位置迫使
> `render/*Renderer → translate` 与 `render/renderer → serialize` 出现反向依赖；
> 归位后 render/translate/serialize 之间无反向边（见 §一实测依赖边），行为零变化
> （纯 import 路径变更，typecheck + 186 测试全绿）。

## 三、边界规则清单（审核红线）

1. **core 零依赖**：不得 import 任何 src 内文件；业务类型只许在 core 定义。
2. **层间只走门面**：app 不得直接触 render/gantt 等内部模块（现状满足）。
3. **渲染层只认 MasterClient**：具体母版实现（masterless/real）在
   `diagramImporter` 装配期注入 `DocumentCore.masterClient`，渲染代码不感知差异。
4. **序列化唯一入口**：一切 XML 部件产出经 `xmlPartsBuilder.build` + 部件工厂；
   形状书写统一走 xmlBuilder 数字格式化，禁止裸模板字符串拼 cell 数值。
5. **错误信息带阶段前缀** `[phase]`（convert/render/translate/…），跨层抛错不吞上下文。

## 四、附注：docmodel 文件级“环”的判定

脚本检测到 `docmodel/model.ts ↔ documentCore.ts` 文件级互引。逐行核实：

- `model.ts` → `documentCore.ts`：`import type { DocumentCore }`（仅类型标注用）；
- `documentCore.ts` → `model.ts`：`import type { PageModel }` + `type { PageId }`（仅类型标注用）。

**双向均为 type-only import** → tsc 编译擦除后无运行时依赖边，ESM 无求值环/TDZ
风险；环仅存在于类型层（两文件互相需要对方的类型做标注）。结论：**保持现状可接受**，
如追求类型层也单向，可把 `DocumentCore/PageModel` 下沉到独立 types 文件或改
documentCore 不反向标注（P2 级可选项，不构成缺陷）。

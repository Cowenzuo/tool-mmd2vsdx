## P-1 自产物预览渲染器（待施工）

> 场景：另一工程用 OpenXML 构造 docx，调用本工程转出 vsdx 后嵌入 Word，
> 嵌入处需要一张预览图（现在留空，只能盲点双击打开）。
> 工程主旨：**全程不依赖本机 Visio**。

### 背景与机制结论（已取证）

- 真实 Visio 产物的缩略图结构（解包 `15-sequence-1-example.vsdx` 实证）：
  `docProps/thumbnail.emf` 加 CT `<Default Extension="emf" ContentType="image/x-emf"/>`
  加根 rels 的 thumbnail 关系。结构可照抄，EMF 无法自产；OPC 不限定格式，jpeg 或 png 都可以；
- docx 嵌入 vsdx 时，嵌入处显示的是**生成方放置的图片**，与 vsdx 包内的 thumbnail
  解耦。所以交付形态就是一张 PNG，由嵌入方放置；
- 图源候选：mermaid SVG（现成，内容一致但风格不同）、自研自产物光栅化（几何同源，
  逼近 Visio）、LibreOffice（外部重依赖）、Visio（违背主旨，排除）。

### 已定决策

1. 嵌入方式：OpenXML 构造 docx，图片由生成方放置，我方交付 PNG；
2. 路线：一步到位直接自研，不做 mermaid 观感 PNG 垫底；
3. 范围：只支持自产 vsdx，不解析任意 vsdx，复杂度差一个量级；
4. 部署环境：Windows 与 Linux 混合；预览图默认行为待定，见下面的待确认清单。

### 方案骨架

- 输入不走 vsdx XML 解析：在 `convertText` 打包前截取页面的 PageContents 树
  （cell 全是本工程写入的字面量，免公式求值），加母版资产（按 `Master=` 查几何与样式）；
- 渲染链：页面树（五几何、母版实例、连接线、文本）到 SVG，再到 Chromium 出 PNG。
  Chromium 已在手，零新依赖；
- 文本建议用 `<foreignObject>` 加 HTML div 让 Chromium 排版，换来自动换行与度量，
  代价是 PNG 输出强依赖 Chromium；
- 背景白底；DPI 默认 150，超过 Chromium 截图边限（约 16384px）时自动降 DPI；
- 母版样式链（LineStyle/FillStyle 加实例 cell 覆盖）需要解析，是 M2 的主要工作量；
- 接口草案：库 `convertText(text, { previewPng: true })` 返回 `result.previewPngBase64`；
  CLI 默认同生 `<stem>.png`，`--no-preview` 关闭。

### 客观上限

- Visio 打开时的公式重算与 glue 重排，离线只能信 V 缓存的保存态值；
- 主题与字体回退细节；1-D 连接线的交互重路由。

### 开工前待确认

1. 验收基准：人工参照集（在装 Visio 的机器导出代表样本 PNG）加自回归像素阈值，
   以及参照集的存放位置；
2. 字体策略：要求环境装 fonts-noto-cjk，或 OFL 字体子集随包（体积加几 MB，
   无再分发限制），或用环境变量指定字体路径；
3. 复杂布局组件的离线边界，例如 sequence 片段，是否接受第一版近似呈现；
4. 超大图的 DPI 策略与 docx 嵌入图幅，是否固定输出宽度；
5. 默认生成 PNG 对已上线对接方的影响：默认开还是显式开关；
6. 输出强依赖 Chromium（foreignObject 排版）是否接受。

## P-4 画布贴合（部分落地）

### 背景

早期只有 sequence 分支写 `DrawingResizeType=2`，class 与 er 还是 `1`，而且内容盒
取自 mmd 的 SVG viewBox（固定 800×600），与内容无关。后果是 Visio 打开时按打印纸
倍数放大页面并整体平移图形：ER 写入 15.34×10.27IN 被打开成 16.04×11.69IN，
sequence-3 写入 11.96×8.01IN 被打开成 23.80×11.69IN 且形状整体右移 7.77IN。

### 结论

页面尺寸等于内容外包围框加两倍半线宽，`kCanvasMargin = 0.0053IN`；全图型
`DrawingResizeType=2`；内容盒按图型精确计算，不再用 viewBox。落地口径见
`docs/开发过程/02-现状.md` 第三节，现象与机制见
`docs/VSDX处理经验/02-坑位与解法.md` 7.11。

### 下一步

1. 审计器把成员行宽度公式 `LISTSHEETREF()!Controls.ROW_1` 映射为容器宽：
   class 与 er 现在被误报越界（class 左侧 0.22IN、er 右侧 0.24IN）；
2. 审计器补 `Sheet.5!Height−Height` 这类公式求值：sequence 片段参数带（MS7）
   现在被母版默认 PinY 误定位；另外底部固定多出 0.005IN（端点半线宽）；
3. 把"页面等于内容盒加减容差"的审计断言并入 `tests/spec.test.ts`，
   现在只有 sequence 断言了 `DrawingResizeType=2`。

### 关联

- 审计脚本 `docs/VSDX处理经验/scripts/canvas-audit.mjs`：母版继承解析、旋转、
  迷你公式求值、NoShow 跳过；
- 选项入口 `source/diag/common.ts` 的 `RenderOptions.drawingResizeType/pageMargin`；
- 当年的探针脚本随 `temp/` 清理，需要时按

## P-3 docProps 字段差异（记录归档）

| 文件 | Visio 保存的 | 本工具生成 |
| --- | --- | --- |
| core.xml | 作者为系统账户、完整时间戳、语言等全字段 | 仅 title 与 creator 为 mmd2vsdx |
| app.xml | Application 为 Microsoft Visio、HeadingPairs/TitlesOfParts 统计、AppVersion 16.0000 | Application 为 mmd2vsdx、AppVersion 2.0 |
| custom.xml | BuildNumberCreated/Edited、IsMetric、TimeEdited | 同结构，加 `RecalcDocument=true` |
| thumbnail.emf | 有，首页矢量封面，保存时生成 | 无 |

字段全集与结构一致，本工具按最小必要填写；解析器按元素名读取，缺省字段按空处理，
不影响打开。需要时（对接方或文档库要求作者、统计、封面预览）再按上表补齐；
thumbnail 议题与 P-1 衔接。
